# VLESS / UDP：先接通功能的实现设计

## 最新执行原则

2026-10-09 用户明确调整优先级：先完成架构接线和可运行功能，遇到真实问题再解决；性能优化、广泛异常矩阵和精细打磨不能继续充当每一步开发的前置条件。本设计继承已确认的 VLESS、REALITY + Vision、ViberMate 自身 SOCKS5 UDP ASSOCIATE、域名排除要求；不把早期开发切片冒充完整支持或正式发布验收。

已有全局代理测试不再阻塞本功能。账号权限、秘密不公开、用户数据不丢失、代理失败不擅自直连仍是实际功能约束。测试只操作隔离数据、临时进程和私有监听，不改正在运行的 App、9666、系统代理或信任。

## 选择：受管 Xray 进程

采用固定版本的官方 Xray 作为 VLESS 协议实现，ViberMate 负责启动、配置、关闭及错误呈现。先以 v26.3.27 的官方产物做真实互通验证，保存实际版本和哈希；不把升级整个项目到 Go1.27、维护协议 fork 或重写 REALITY/Vision 作为开工前提。原调查中对进程内全局状态和后台任务的顾虑，由独立进程的生命周期隔离处理，再根据实际观测补强。

Xray 只是 ViberMate 内部的出口实现，不替代 ViberMate 自己的 SOCKS5 入口。内部连接使用受管的回环端点和随机认证信息；用户无需自行运行或配置 Xray。开发期可显式指定隔离的内核路径，发布时再补齐受管内核分发、来源和许可证材料。不接受任意 Xray 配置或开放管理接口。

每个已选定的出口配置是不可变的；修改配置用于新操作，已有流使用原配置。主 Runtime 保持现有 Go 工具链和模块依赖。内核启动失败向上报告，不切到 Direct。

## 接线位置

1. `internal/vlesscore`：将进程、配置和内部 SOCKS 协议封装在一个 Module。对调用者提供 TCP 连接、固定目的地的数据报连接以及 Close；调用者不接触 Xray JSON、进程 ID 或内部认证信息。先通过真实 TCP/UDP 回包证明这条链路。
2. `internal/egressnetwork`：现有出口选择结果继续有效，增加 VLESS 出口和数据报连接。目标域名先做直连规则匹配，再解析；不匹配则继续使用配置的 DNS/DoH 和代理。
3. `internal/socksproxy` 与 Runtime/host 接线：ViberMate 自己处理 SOCKS5 认证、CONNECT 和 UDP ASSOCIATE。TCP 控制连接拥有 UDP association 的生命周期；使用已有 Capture/网络准入信息，UDP 不伪装成模型或工具请求。先默认绑定回环，远端监听由显式服务器配置选择。
4. `egressprofile`、owner-control 和 Flutter 出口编辑器：导入 VLESS 链接，保存秘密引用，展示脱敏节点信息；提供直连域名列表。沿用账号 > 流量策略 > 全局 > 内置直连的已确认优先级。

`Policy` 当前用于值比较及冻结目标的 map key。域名规则采用规范化的不可变可比较值（内部保存规范编码），不直接放可变 slice，也不先重做整个策略系统。旧配置保留既有明确选择；本功能不自动迁移真实运行目录。

## 用户可见行为

- 首个可交付 VLESS 功能覆盖 **REALITY + Vision**，不以普通 TLS/TCP 代替。
- ViberMate 自己的 SOCKS5 客户端可以使用 UDP ASSOCIATE，数据经 VLESS 出去并收到原目标回复。仅跑通 Xray 自带 SOCKS 是实现基础，不算完成此功能。
- `github.com` 表示该域名及子域名，`*.github.com` 仅表示子域名。匹配后使用 Runtime 主机的系统 DNS 和直连；不是代理失败后的回退。IP 目的地址不猜测域名。
- 普通 TLS 节点使用系统信任或该配置导入的自有 CA；REALITY 使用自身公钥/认证参数，不能拿跳过证书验证替代它。普通 TLS 的不安全跳过选项如提供，必须显式、默认关闭并标明风险，不自动启用。
- UUID、认证参数、内部密码不进入普通配置导出、审计或错误文本。配置界面只显示足够识别节点的信息。

## 首轮只验收真实功能路径

先做两个真实演示：TCP 请求成功，以及客户端 → ViberMate UDP ASSOCIATE → REALITY + Vision → 私有 UDP echo → 客户端。再证明命中直连域名时走系统 DNS/Direct、不命中时走代理。关闭客户端控制连接能结束关联；错误配置能清楚报错而不误走直连。

基本取消/关闭、认证隔离和数据完整性随功能实现。广泛模糊测试、极限容量、全面平台矩阵、性能与长期运行，在上述链路接通后集中推进；不能为了尚未观测的风险先无限扩张准备工作。正式发布仍需与实际范围相称的构建、来源、安装和安全核验。
