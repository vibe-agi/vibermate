# 全局默认网络出口设计

日期：2026-10-05。源码核查基点：`938766bd17bbe3796096b3c8cf3a62f91e44fb96`。用户已确认下述优先级并要求加入本次开发，并在书面设计确认中选择“按设计推进”；本文是已批准架构设计，尚未实现。父设计：`2026-10-03-production-readiness-design.md`。

## 用户可理解的规则

账号明确选择的出口 > 当前请求所属流量策略明确选择的出口 > 全局默认出口 > 内置直连。没有账号或流量策略的请求跳过对应层。明确选择“直连 · 系统 DNS”也是选择，不能被全局代理覆盖。账号“跟随流量策略”表示不覆盖：独立账号操作没有流量策略，因此继续落到全局默认。

这里的 fallback 只表示**未配置时的继承**。代理不可用、DNS/TLS 失败、取消、配置读取失败，都不能触发直连或换代理重试。全局设置覆盖的是当前连接的 ViberMate Runtime 管理的出站请求，不修改 macOS/Windows 系统代理、终端环境变量、外部浏览器或其它程序。

## 方案与取舍

采用现有 `egressprofile` / `egressnetwork` 中的统一出口选择与冻结，再交给各运输实现。不通过 `HTTP_PROXY` 或全局替换 `http.DefaultTransport` 实现：那些方式覆盖不了当前自定义 TLS/SOCKS、原始转发、浏览器版 UI，也会破坏明确直连和本地控制链路。也不把所有现存 `Direct()` 一律替换成默认代理：其中有明确用户选择、本地专用传输和历史冻结记录，不能混淆。

不新增独立代理服务、泛化 URL 转发接口或新的运行时依赖。网络选择只决定怎样连接已有合法目标，不能授予目标访问、工具执行、账号使用或证书信任权限。

## 配置与统一选择

- 全局默认持久化在 Runtime 数据库，与当前 Runtime 实例的数据目录同范围；不是某台 UI 的本地偏好。远程连接时界面明确显示这是服务器出口；`127.0.0.1:7890` 指服务器所在机器。
- 存储一个带单调 revision 的默认设置，选择值为某个已发布出口的**精确 ID + revision**，或者“未设置”。未设置才使用内置直连。不能根据名称或当时列表第一项猜测默认。
- 使用现有 owner-control 鉴权、expected revision 与幂等命令模式。只接受已发布、完整校验的出口引用；不接受调用方注入 policy 对象、任意 URL 或伪造 revision。提交不确定时按实际持久状态核对，不能仍从旧缓存给新请求发放出口。
- 修改出口方案会产生新 revision，不暗改已选默认的旧 revision。编辑当前默认方案后，界面提供明确的“将此版本设为默认”；显示当前实际默认版本，避免“列表 r2、实际 r1”不透明。
- 统一选择返回不可变的实际 `ProfileRevision`、选择来源（账号/流量策略/全局/内置）及所用全局设置 revision。它没有秘密，也不是发送凭据。所有目标、账号、当前权限、Offline Hold 与审计检查照常执行。
- 显式出口不需要读取全局默认才能生效；需要继承却读不到有效默认设置时停止该操作并报告，不能将错误解释成“未设置”。持久化的“未设置”与读取失败是不同状态。

## 继承与兼容

现有账号 `egressProfile: null` 已表示不覆盖，保留这一含义。为流量策略和对应原生工具路由增加真正的“使用全局默认”选择，不能借用内置 Direct 的 ID 表示继承。接口与 canonical 存储必须明确区分继承、显式直连及显式代理；缺失的必需字段、损坏引用不得自动当继承。

旧发布配置中的具体 `egressProfile`（包括 Direct）保持显式选择，原 JSON 字节、Environment digest、revision、账号配置和历史审计不重写。新增策略默认选择继承；旧策略若希望跟随全局，由用户显式切换并发布新 revision。UI 必须清楚显示哪些旧策略仍是直连。

原生工具权限仍每 profile 默认关闭；网络继承不能自动开启它。原生工具继续使用客户端原凭据，不继承模型账号的出口覆盖；它只按自己所属流量策略选择出口，再落到全局默认。迁移、保存和恢复不能把“继承”转成新的工具访问授权。

## 冻结时机与在途行为

全局默认不是运行中连接的动态变量。每次新出站逻辑操作在 Offline 排队、凭据刷新、DNS、连接或出站审计开始之前选定一次实际出口；同一操作的探测、等待、发送及终态共用该副本。入站 Activity 的请求开始记录仍可先发生，此时不宣称账号或实际出口已经选定，避免丢失早期失败的可观察性。默认设置随后变化，只影响之后开始的新操作，不重连、不取消、不重新发送旧请求。已有 TCP 隧道和正在流式返回的请求继续使用其原出口。

调用链需要多个步骤时保持一致：一次“查询详情后使用重置券”共用其已冻结账号出口；首次 OAuth 从启动登录时冻结默认出口，授权码兑换不能临时换路，也不能制造假 AccountRef；已有账号刷新与依赖它的新请求使用同一次合法账号租约的网络上下文。浏览器打开授权页仍由浏览器自己的网络设置决定。

Environment 发布内容与 digest 描述用户选择；实际网络选择是另一个不可变执行事实，不能把解析后的全局设置写回旧 Environment，伪称同一个 digest。现有真实 RequestLease/账号租约、原生绑定和出站请求构造负责携带有效结果，原始 source/authority 不因全局出口改变而重标。

同一原生逻辑调用的回调/恢复/代理续接必须保留既有精确关联与冻结出口要求。需要沿用原逻辑操作出口时从已有真实租约/StreamAuthority取得，不凭 SQL 历史或 operation ID 重建权限。无法满足原关联时拒绝恢复，不更换出口或重发 POST。需与已采用的 upstream-continuation 计划联调，不能各自创建第二套恢复机制。

## 必须覆盖的真实出站入口

| 入口 | 选择与边界 |
| --- | --- |
| 托管模型请求及其辅助读取 | 账号显式优先，其次请求所属策略，再全局；保持模型账号和工具账号隔离。 |
| 额度、历史用量、重置券详情/兑换、账号模型列表、手动/自动 OAuth 刷新 | 账号明确选择优先；独立账号操作没有流量策略时使用全局。 |
| 首次 OAuth 授权码兑换 | 登录开始时冻结全局；不把原账号 access token 附加给 token endpoint。 |
| 公共模型/价格目录 | 同一次操作冻结全局；保留固定来源、响应大小、HTTPS 与重定向限制。 |
| 原账号/原目标转发、已授权原生 MCP 工具 | 使用各自策略明确选择或全局；仍先通过原有目标、数据分类、ToolDecision、once/receipt 检查。 |
| 已允许的盲 CONNECT 和普通明文外网转发 | 当前网络准入规则不变，只把原硬编码直连改为实际冻结出口；无新允许目标、私网豁免或负载读取。 |
| Offline 恢复/可达性探测、SOCKS 与 DoH | 探测必须跟相同目标和出口；DoH 经代理还是直连由该出口方案决定，不递归套用全局。代理服务器的引导连接本身不能再经自己代理。 |
| 主动检查版本更新 | Flutter 当前直接访问 GitHub，需转为 owner-control 的固定版本信息读取，由 Runtime 用全局出口访问精确官方 release endpoint。不是通用远程 URL fetch；继续禁止重定向、超长响应和自动安装。 |

更新检查仍由用户主动触发。界面保留本机 App/CLI 的版本与安装渠道检测，仅将固定的远端 Release 元数据读取交给所连接 Runtime；不能用服务器安装渠道替代本机信息。旧服务器不支持该接口或 Runtime 暂不可达时明确显示不可用，不悄悄退回界面直连。浏览器打开已校验的发行页面仍属于外部浏览器。

本地控制、Runtime 连接与 CA 引导、localhost OAuth 回调、明确本地专用的回环提供者连接不进入全局外网代理，避免配置错误导致无法打开设置或自代理循环。`servertransport` 的客户端到选定 Runtime 的连接保留既有信任和目标规则；它不是该 Runtime 向上游的出口。外部浏览器/下载器/Homebrew 和未经过 ViberMate 的客户端流量不在此设置控制内。不存在的插件下载等功能不得因目的枚举中有名称就宣称已经支持或新增实现。

Task2 独立审查 I1 对上述既有边界的实现细化（不增加可访问目标）：已验证实际提供者目标的类型为 `loopback_cleartext` 或 `private_cleartext` 时，在读取秘密、凭据准备、Hold、探测和发送之前处理其原有 direct-only 约束。先按原优先级选账号/策略的显式配置；获胜的明确直连保留原来源与 DNS 配置，获胜的显式代理被拒绝，不能换用较低优先级配置。只有二者均未明确选择时，使用精确内置 Direct，不查询全局设置；单独记录来源 `transport`、全局 revision0，表示连接类型约束而不是账号/策略选择或全局缺省。不根据域名字符串或泛化私网猜测新增豁免；所有 HTTPS（包括 HTTPS 回环）保持原普通选择规则，现有明文实际 peer/地址/端口检查不变。目标消费端和新审计记录必须拒绝将此来源用于非 direct-only 目标，不能将本地租约借给公网请求。正常界面不支持的 typed 本地 Codex OAuth 账号组合，也应在秘密检查/自动准备前拒绝（最终认证器原本就拒绝该目标）；独立手动刷新实际访问固定 HTTPS token 目标，仍用原账号/全局选择，不能按账号 Origin 猜成本地请求。

## 可解释的界面与审计

“网络出口方案”页新增“设为默认”和“当前默认”标记，另有清晰的当前默认摘要；内置直连仍可选但不可编辑。未设置显示“未设置，使用直连”。保存未确认、冲突和失败不得显示已经切换。

账号保留“跟随流量策略”，说明改为“有流量策略时跟随策略；其它账号操作使用全局默认”。策略选择器提供“使用全局默认”；旁边显示当前解析结果，且与“明确使用直连”分开。正在运行任务提示仅说明新操作生效，不自动中断或要求重启。

保持英文/简体中文、键盘可达、390px 窄屏和 200% 字体。用户主界面展示方案名、代理类型和继承来源，默认不暴露 ID、哈希或内部 revision；诊断页可展示精确版本。

出站审计记录实际所用出口的 ID/revision、明确的选择来源及适用的全局设置 revision。沿用原 purpose/authority/AccountSettingsRevision 等真实含义，不能把全局值塞进账号 revision、RuleID 文本或 Raw 字段。旧记录缺少新来源时按历史未知展示，不追溯伪造。初始/终态、Offline 探测、native 绑定与实际 socket 选择必须一致。`transport` 来源只允许上述合法 direct-only 提供者目标、精确内置 Direct 和 revision0，界面说明为“连接类型要求直连”；它不是四层优先级中的第五项，不改变 `builtin` 必须绑定真实未设置默认 revision 的含义。

## 数据升级与交付顺序

沿用用户已经允许的经过备份和验证的安全升级，保留全部账号、秘密引用、配置、历史及权限。全局设置和必要的选择/审计字段需纳入最终 schema、v1 升级、备份恢复及故障验收；不触碰冻结的 v1 规范，不重置数据，也不迁移正在使用的用户目录。与同一未发布版本的 native continuation schema 修改串行合并；严拒无法证明兼容的旧私有 v2，而非静默接收。

当前 native-claim Task2 保持唯一代码写者，完成正常/竞态/精确客户端诊断和独立复核后，再执行本设计的独立实施计划。本功能进入本次整体生产验收和发布范围；不以源码设计、若干 HTTP 单测或 UI 默认标记替代真正的全入口验证。原有 SSE、CA、记录超时、完整客户端矩阵、soak 和发布门槛不取消。

## 验收标准

1. 真实临时 Store 的默认保存/重启/清除、expected revision 冲突、回滚、commit-then-error 与恢复；账号/策略/全局/内置四层优先级，显式直连覆盖，损坏默认不直连。
2. 真实 SOCKS + 严格 TLS/DoH 合成服务器证明上表每个存在入口确实到达所选代理，并分别验证代理不可用时原目标直连次数为零。不能仅用 mock 收到 policy 或 `http.Proxy == nil` 推断网络路径。
3. 在 Offline 排队、OAuth 登录/刷新、重置券详情读取后、SSE 流式返回及原生恢复中切换全局默认：已有操作保持精确原选择，新操作选择新版本，无额外发送/兑换/令牌刷新，无部分混合配置。
4. 原登录、默认关闭的 MCP、审批消费、原目标同源、私网保护、证书验证与客户端到 Runtime 连接均无权限扩张；真实 UI 更新检查不再自行旁路外网。
5. 旧 Direct 配置/历史字节和摘要、完整 populated-v1 升级、数据备份与恢复、原生 frozen-binding 校验全部通过；所有新增选择状态往返一致。
6. 设置页、账号/策略选择器、更新检查的 Flutter 正常/失败/竞态与窄屏大字体测试；Go 正常/定向 race、仓库规则、跨编译以及独立 spec/security/quality review。
7. 在最终同一源码的完整客户端、60 分钟两 profile 受控运行和打包安装验收中加入全局默认与显式覆盖场景；未验证范围如实列出，完成前不宣称全局所有请求已接入。

## 自检

与用户批准规则一致：全局兜底不压过显式选择，代理失败不换路，在途连接不切换；首登 OAuth 和实际 Flutter 更新路径均有归属。账户缺省、策略继承、持久化未设置、读取错误四种状态未合并；旧明确直连保持兼容。原生工具原凭据/授权边界、真实本地控制引导、审计来源和安全数据升级均有对应验收。没有实现新下载器、系统代理或真实账号操作。书面设计已获用户确认，下一步为详细实施计划及串行 TDD/独立复核。

源码事实已在上述固定提交核对：`provideraccount/{account_read,settings,refresh}.go` 和 `manager.go` 的账号租约、`providertransport/{plan,runtime_fetch,account_read,account_reset,transport}.go` 的实际 profile 传递、`codexoauth/login.go` 首登空 AccountRef、`originaltransport/transport.go` 的自定义 SOCKS dialer、`blindtunnel/{dialer,probe}.go` 的直连缺口、`environment/{types,aggregate,snapshot,client_tools}.go` 的持久化与摘要、`desktopcontrol/egress_profiles.go`、`runtimepersistence/egress_profile_repository.go`，以及 Flutter `product_update_api.dart` / `egress_profile_editor.dart` / `settings_view.dart`。独立只读出站清单与主控逐项自检一致；这里只证明当前调用关系，不是新功能测试通过。
