## Adopted design

Model a logical SSE stream separately from an HTTP attempt. Preserve the original logical RPC while a bounded, authenticated same-stream GET can recover it. Finish each physical egress audit when that HTTP attempt ends. A fresh GET owns its own observed callback authority; it never borrows a tools/call. A completed GET send receipt stays unusable for sending; a separate, expiring observation capability permits the already observed callback to obtain its own ToolDecision and once-only send.

This is more than accepting new GET bytes. Reject the two smaller alternatives: a session-global event cache cannot prove stream identity; allowing every completed GET parent from SQL alone cannot prove a live, exactly observed callback or the original Store-issued receipt. Also reject keeping a dead HTTP audit open until the user replies: it confuses transport bytes and duration with callback lifetime.

## Bounded addendum: concrete trusted-Go interface (root review)

Proposed names below are internal Go types/methods, not wire DTOs. `StreamAuthority` and `CallbackAuthority` have only unexported token/issuer fields, no JSON representation or public constructor. A repository-owned issuer, analogous to `StartReceiptIssuer`, creates/checks them; another issuer's lookalike is rejected. Its private bounded registry holds immutable origin receipt + binding, absolute deadline, stream terminal/revoked status, registered callback facts, and child-operation associations. `nativemcp` retains the wire/event ledger. No method retrieves an authority by operation ID.

```go
// Add to the internal repository interface; argument structs contain no raw callback data.
OpenObservedStream(ctx context.Context, receipt StartReceipt, frozen Binding, configuredLifetime time.Duration, at time.Time) (StreamAuthority, error)
RegisterObservedCallback(ctx context.Context, stream StreamAuthority, facts CallbackFacts, at time.Time) (CallbackAuthority, error)
BindObservedReply(ctx context.Context, child ID, binding Binding, callback CallbackAuthority, witness RegisteredParentWitness, at time.Time) error
BindRecoveryGET(ctx context.Context, child ID, binding Binding, stream StreamAuthority, at time.Time) error
ValidateLocalReplay(ctx context.Context, stream StreamAuthority, at time.Time) error
FinishAttempt(ctx context.Context, receipt StartReceipt, in PhysicalFinishInput) error
CompleteStreamRPC(ctx context.Context, stream StreamAuthority, in LogicalFinishInput) error
RetireObservedCallback(ctx context.Context, callback CallbackAuthority, at time.Time) error
RetireObservedStream(ctx context.Context, stream StreamAuthority, at time.Time) error
```

`CallbackFacts` is `{RPCIdentityDigest, RequestDigest Digest; Kind CallbackKind}` with a closed supported-kind enum. It describes a parser observation; alone it grants nothing. `PhysicalFinishInput` is `{Outcome, Reason string; Counts *ObservedCounts; ObservedAt time.Time}`, where `ObservedCounts` holds nonnegative `BytesIn, BytesOut int64` and nil means both unknown. `LogicalFinishInput` has only `{Outcome, Reason string; ObservedAt time.Time}`. Every method validates closed outcome/reason combinations. These are transport-module composition seams, not management endpoints.

Issuance: after `sendCommitted` and authenticated SSE header validation, the parser calls `OpenObservedStream` exactly once. In one writer transaction under the issuer lock, Store checks the actual Start issuer against reconstructed StartFacts, started origin, exact frozen Binding digest, once/attempt provenance, active owner/session/route/assignment/permission, and nonterminal audit. Store derives expiry as the earlier of the original attempt start + CallLifetime and applicable session/authority limits; the caller cannot extend it. It registers the opaque authority only after a known successful transaction. Commit-then-error yields no handle; no recovery from a database lookup. The parser calls `RegisterObservedCallback` only for a complete supported observed request, after HMAC production where sensitive. Registration requires a currently attached, nonterminal stream and deduplicates callback identity; no fresh callback registration after stream terminality. Fresh GET may register before any catalog exists.

Binding: new callbacks use `BindObservedReply`; generic `Bind` must reject new `server_reply` bindings so callers cannot bypass registration. Store checks callback issuer/liveness, exact parent/scope/digests, and `witness.Verify(child,binding)`; then performs the existing durable binding checks and registers the exact child ID + binding digest against that callback. Only one child identity can claim it. This association remains until terminal cleanup, so approval retries for that same child work while another reply cannot reuse it. Ordinary ping observer and sensitive producer consume the registered stream/callback context; replacing the Kind restriction alone is insufficient.

Rechecks: `RequestApproval`, `DecideApproval`, `Start`, and the existing `VerifyStartReceipt` call path through `nativeExecutionAuthority`/parent validation check the child association's live callback, origin receipt issuer, original immutable once/audit provenance, current authority and deadline. Change that private parent-validation helper, not `VerifyStartReceipt` or its requirement for the **child's** nonterminal exact audit. Allowed origin audit states are the registered initial nonterminal attempt, a completed GET, or failed/transport_failed physical attempt; never an arbitrary uncertain/revoked/unknown-provenance origin. The original GET receipt remains invalid for sending once its audit is terminal. Successful reply completion consumes the registration atomically with durable completion; retain only a bounded tombstone for replay deduplication.

Revocation: serialize registration/consumption/retirement and authorization checks with the repository issuer lock in consistent lock order. Durable OFF/stop/owner/session revocation remains decisive in every transaction even before in-memory notification arrives. Local cancellation, stream protocol failure and hard expiry retire the exact stream registrations; RPC completion retires POST-owned callbacks but keeps a terminal replay token. Clean GET EOF completes its native operation/audit while preserving its existing callback registrations until consumption/deadline. Explicit callback retirement is idempotent and closes that child's pending/unconsumed approval through existing lifecycle rules. Revoke, CloseSession, Recover and repository shutdown clear the affected issuer registrations; restart creates a new issuer. A commit-outcome error invalidates the relevant in-memory authority and follows uncertainty handling, never reissues it. No schema column is needed for these process-lifetime capabilities.

Recovery binding: after the executor resolves and exclusively attaches an exact retained cursor, `BindRecoveryGET` verifies a live **unresolved** stream, original Start provenance and active scope, requires a new body-free GET binding for the exact session/route, and records child→stream privately. The existing GET Start/Verify path additionally rechecks this association. Cursor wire and ordinal remain verified by the private stream module; they do not become caller-supplied SQL authority. The GET has its own receipt/once/audit. It never consumes the original receipt for another send.

Terminal replay: branch **before Receive/Bind/Start**. If the exact cursor has a complete retained suffix ending in the original terminal result, validate current captured admission and call `ValidateLocalReplay`; it permits a terminal replay token under active exact scope and deadline, but grants no outbound permission or new callback registration. Return only the cached exact suffix locally; create no egress attempt or fabricated Start. If the suffix is incomplete, recovery requires `BindRecoveryGET` and thus an unresolved stream. A terminal record can never take the outbound branch. Replay delivery failures preserve the cache until its deadline; semantic completion/retention/approval effects never run again.

Bytes: `FinishAttempt` checks the actual issuer receipt and exact initial once/audit, closes that audit once, and copies its count projection to the origin native operation. It leaves a POST logical RPC started; a listening/recovery GET has no originating RPC and completes its own native row with its physical outcome. Pass `Counts == nil` to the existing egress `UnobservedByteCounts` field independently of physical Outcome; failed/transport_failed can therefore have either known counts or NULLs. The existing egress representation supports an atomic known pair only: if either direction is unobserved, persist both unknown, never substitute requested ContentLength or zero. `CompleteStreamRPC` changes only logical state/reason/completed time and barrier as applicable; it does not update bytes or the terminal audit. Recovery GET counts never augment the POST row. Legacy `Finish(TerminalInput)` keeps its ordinary behavior by composing private helpers; it is not used to manufacture recovered counts. Cleanup of a suspended RPC preserves its existing initial-attempt count projection, including NULL, while recording logical uncertainty.

Required focused additions: completed-GET callback survives EOF but original receipt cannot send; missing child registration denies at each approval/Start/Verify seam; local terminal replay yields zero Receive/Start/outbound calls and rejects OFF/expired scope; failed physical attempt with known counts and with NULLs both later complete logically without count/audit mutation; cross-issuer, commit-then-error, revoke-vs-Start and restart all deny capability reuse. No remaining DDL decision is exposed by this interface; Store registry bounds and lock ordering are implementation obligations, not new persistent authority.
