## Addition to native-store Task 3: commit-owned receipt seam

Cancellation is not body-free authority. The controller-approved unreleased-v2 `cancel_rpc_id_digest` binding refinement makes the exact typed target available to operation-ID-only Start. Bind derives the opaque digest from the immutable domain binding; Start/Verify recheck actual same-session target operation/binding/owner and current active state within SQL. A target that completed after Bind cannot yield a cancellation receipt. Keep the cancel-only insert constraint, NULL for other kinds, frozen-v1 preservation and exact schema parity; no raw IDs, caller grant or memory-only target relation.
Public Go domain factory is needed because another package cannot construct private fields; it only creates an issuer identity, not Store authorization.
```go
type StartFacts struct { OperationID ID; AttemptID string; AuthorityRevision, OwnerEpoch uint64; BindingDigest Digest }
type StartReceiptIssuer struct { /* private per-Store nonzero random identity */ }
func NewStartReceiptIssuer() (*StartReceiptIssuer, error)
func (*StartReceiptIssuer) Issue(StartFacts) (StartReceipt, error)
func (*StartReceiptIssuer) Check(StartReceipt, StartFacts) error
// ADD to Repository; retain the existing Start signature and receipt getters:
VerifyStartReceipt(context.Context, StartReceipt, time.Time) error
```
Extend StartReceipt's private fields with issuer identity, owner epoch, and binding digest. Issue validates ID/attempt/revision bounds; Check compares every frozen fact plus issuer identity. No raw auth, public approval flag, persisted issuer token, serialization, unsafe reflection, or receipt reconstruction port. A zero issuer/receipt fails closed; random identity construction can fail and must stop Store opening.
Store.Open creates one issuer; private native repository owns it. Issue is called only after the existing atomic Start transaction's commit is positively verified. Approval consumption, once tombstone, native audit, started operation and event remain one transaction. rollbackThenError/commitThenError uncertainty returns ErrUnavailable and a zero receipt, even if durable reconciliation later finds a committed claim; never mint a delayed resend receipt.
Verify enters the same Store operation/close gate and reads one consistent authoritative transaction: nonterminal started operation, immutable binding, once operation/attempt/authority revision, active nonterminal audit, current active scope revision/owner/expiry, actual eligible Capture and assignment, current ON Environment, and kind-specific session/catalog/parent predicates. It derives StartFacts from rows and then invokes its own issuer.Check; caller facts never substitute for SQL evidence.
Finish/revoke/disable/recover/close/assignment or owner changes invalidate verification. Recover replaces the issuer as well as performing existing durable revocation/uncertain/barrier work. Same path reopened or copied to another Store has a fresh identity; old receipts never restore from DTOs. Same-Capture reenabling/new session cannot revive prior receipt authority.
Verification is point-in-time permission: transport calls it immediately before its single send under the actual owner cancellation context. A copied receipt is not a new Start or retry license; receipt verification alone does not make a later revocation/network write atomic. Do not promise it cancels bytes already sent.

## Addition to native-store Task 2 and later parser: frozen catalog provenance
CatalogEvidence is opaque data provenance, not a grant. A domain constructor cannot establish that bytes arrived from an authenticated network response. Trusted Go composition supplies that fact through the actual parser; external HTTP inputs can never select an observer or fabricate its observation objects.
```go
type CatalogScope struct { Capture captureidentity.Reference; Plan environment.ClientToolPlan; AssignmentRevision, OwnerEpoch uint64; SessionID ID; SessionRevision, CatalogGeneration uint64 }
type CatalogPageObservation struct { ExactRequest, ExactResponse []byte }
type CatalogObserver struct { /* private frozen scope and observation identity */ }
type CatalogEvidence struct { /* private scope, complete frozen definitions, digest */ }
func NewCatalogObserver(CatalogScope) (*CatalogObserver, error)
func (*CatalogObserver) Observe([]CatalogPageObservation) (CatalogEvidence, error)
func (CatalogEvidence) Scope() CatalogScope
func (CatalogEvidence) Digest() Digest
// REPLACE existing Repository.SetCatalog's digest parameter:
SetCatalog(context.Context, ID, uint64, CatalogEvidence, time.Time) (uint64, error)
// ADD BindingInput.CatalogEvidence *CatalogEvidence; PublicToolDefinition is
// retained only as unproved compatibility input and still cannot publish a name.
```
ExactRequest/ExactResponse are memory-only cloned inputs. Observe checks one bounded legacy tools/list envelope per page, duplicate/trailing/batch rejection, type-sensitive response/request-ID equality, coherent cursor progression, terminal completion, and unique tool names. Adopted bounds are 8 MiB total catalog, 1024 tools, at most 32 pages and existing 1 MiB per request/event defaults; reject overflow, incomplete catalogs, errors and ambiguous definitions. Native tools/call still has exactly one intent.
Root-adopted catalog identity is the COMPLETE PUBLIC projection, not the complete wire response: SHA-256 of domain-tagged canonical JSON containing every bounded public definition (name/schema/description and allowlisted known public annotations), sorted by unique name. JSON objects sort keys; numbers retain exact json.Number semantics. Exclude RPC IDs, cursors, auth/proof/elicitation values, `_meta` and unclassified extensions BEFORE hashing; those raw values/digests never enter storage. Empty complete catalogs differ from no catalog.
Public projection includes every tool, rather than selecting only the called tool; reject missing/duplicate/conflicting definitions and invalid public schemas. Known sensitive schema/description paths require explicit field suppression or rejection BEFORE hashing; never promise generic free-text secret detection. Full wire pages stay memory-only for observed-origin/session/correlation checks. Metadata/readOnly annotations never admit sends.
Parser creates its observer only after actual original-client-authenticated exchange at the exact frozen HTTPS origin/path, response/request/session correlation, and owner/Capture match. A caller-selected URL, login boolean or supplied digest is insufficient. Original HTTP auth stays in its existing memory-only transport owner; neither CatalogScope nor observation includes credentials or credential fingerprints. Redirects/changed destination/unauthenticated or unsolicited responses cannot produce evidence.
CatalogScope.SessionRevision is the post-SetCatalog revision (expected+1); CatalogGeneration is current+1. SetCatalog derives those values and the exact Capture/Plan/assignment/owner/session from authoritative ready-session rows, compares every field, CAS commits digest+generation and cancels unconsumed questions. It stores neither observer identity nor full catalog. Overflow fails closed. Only after its returned revision matches does parser publish the evidence for bindings.
NewBinding checks evidence is nonzero and exactly matches binding scope, frozen Plan/route/target/contract/owner/session revision/generation and CatalogDigest; it finds the actual single tools/call intent name and function definition in the complete immutable catalog, validates the complete mapped protocolcore definition, and applies <=256-byte UTF-8 `[A-Za-z0-9_.:/-]+` naming. Invalid supplied evidence rejects; absent evidence keeps ToolName empty. Selected name enters existing binding digest. Definitions/schemas/descriptions never enter Binding/Operation DTOs or OFF/meta rows.
Bind rechecks catalog scope/digest against the actual session; Start rechecks current catalog except existing frozen-parent server_reply rules. A digest is membership evidence only when the complete observed catalog was validated; it cannot prove observed/authenticated origin by itself. Existing server_reply parent/outstanding-request evidence and decisions remain required.

## Addition to later transport: ephemeral keyed sensitive callback binding
The reviewed NewBinding currently directly SHA-hashes whole server_reply RPC, params/group and accepts ServerRequestDigest. Known sensitive elicitation/proof/auth traffic must branch BEFORE any such raw SHA or evidence insertion. Interim rejection is fail-closed only while the seam below is unfinished; it is not the final advertised-default-callback solution or a compatibility completion claim.
```go
type SensitiveScope struct { Capture captureidentity.Reference; Plan environment.ClientToolPlan; AssignmentRevision, OwnerEpoch uint64; SessionID ID }
type SensitiveObservation struct { /* private profile-recognized kind and paths */ }
func NewSensitiveObservation(kind string, paths []string) (SensitiveObservation, error)
type SensitiveBindingHasher struct { /* private random key, scope, outstanding parents */ }
type SensitiveParent struct { /* private hasher identity, operation, RPC identity, request MAC */ }
type SensitiveBindingContext struct { /* private hasher + registered parent */ }
func NewSensitiveBindingHasher(SensitiveScope) (*SensitiveBindingHasher, error)
func (*SensitiveBindingHasher) ObserveParent(ID, []byte, SensitiveObservation) (SensitiveParent, error)
func (SensitiveParent) RequestDigest() Digest
func (SensitiveParent) RPCIDDigest() Digest
func (*SensitiveBindingHasher) BindReply(BindingInput, SensitiveParent) (Binding, error)
func (*SensitiveBindingHasher) Close()
// ADD BindingInput.SensitiveObservation *SensitiveObservation and
// BindingInput.SensitiveContext *SensitiveBindingContext; neither is serialized.
```
Create one crypto/rand 32-byte nonpersisted key per actual authenticated Session/Capture/original-client-owner scope. Validate/freeze SensitiveScope; key creation failure denies admission. A public Go factory alone proves no origin or send permission. Actual parser owns the hasher and parent registry, never exposing either to HTTP/control/plugin JS; registered source comes from the authenticated same-session upstream stream, not client-provided proof flags.
ObserveParent validates the complete bounded observed server request and existing triggering parent operation, type-sensitive RPC identity and profile-recognized sensitive classification BEFORE any digest producer. It computes HMAC-SHA256(key, length-framed domain label + frozen public scope + exact request), plus a distinct-label MAC of type-canonical RPC identity, keeping only required correlation memory and opaque MACs. Bound outstanding parents to the existing 1024 pending-operation limit; duplicate/conflicting IDs fail closed. The request MAC enters existing child ServerRequestDigest; parser uses BindReply's Binding.RequestDigest plus parent.RPCIDDigest for Receive, never a SHA of raw sensitive request/reply/ID/proof. No new server-request enum or schema row is invented.
BindReply verifies the registered parent belongs to this hasher/session/Capture/original owner, matches ParentOperationID and the exact reply RPC ID, and has not been answered/canceled/expired. It privately creates SensitiveBindingContext and calls NewBinding. NewBinding checks context/scope and sensitive classification FIRST, then HMACs exact reply/request, canonical params/result-or-error and intent-group evidence using distinct framed labels; it overrides caller ServerRequestDigest with registered parent MAC. No direct SHA of sensitive bytes is evaluated anywhere on this branch, including Receive/inbound-ID producers.
Opaque MAC Digests remain 32 bytes and fit existing SQL columns; bindingDigest hashes only frozen public authority plus these opaque MACs. Binding retains no key, context, raw proof, callback payload or registry handle. Ordinary nonsensitive tools/call ExactRPC/params/group SHA semantics stay unchanged. Known-sensitive input without a valid registered context rejects BEFORE hashing; parser classification omission is a producer bug caught by actual parser tests, not something private Go fields magically prevent.
Parser marks parent consumed only through the existing durable decision/Start/once path; canceled or uncertain reply cannot automatically re-register/resend. Bind and Store.Start still verify actual persisted parent/session/owner/catalog scope and all existing ToolDecision predicates; neither HMAC nor registration grants approval. A changed owner/session uses a new key. Close/restart drops the key and parent registry, revokes old sessions through Recover, and preserves once/barrier evidence; persisted MACs cannot reconstruct credentials/proofs or authorize replay.
