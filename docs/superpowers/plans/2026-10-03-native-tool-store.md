The domain imports no toolapproval package. OperationID is a definitive alias of validated ID for this draft; transport may use either without conversion. Binding clones pointer/slice values and exposes copied metadata; Operation target/Environment/owner is decoded from immutable native history, never mutable profile. Do not read body bytes, headers or params in these joins. ToolName comes only from immutable binding.tool_name: PublicToolDefinition must validate, belong to the parser's observed frozen catalog and match the actual tool intent; names must be <=256 bytes, valid UTF-8, contain no controls or whitespace, and match a public identifier grammar `[A-Za-z0-9_.:/-]+`. If catalog/name provenance or policy is unproved, constructor persists empty and UI uses generic native-action copy. NewBinding hashes the selected safe name with its immutable metadata; it grants no workspace or approval authority. No agent/assistant label is inferred.

Closed request binding: initialize/initialized/tools_list/ping/cancel/get_stream/delete_session use empty ToolIntent groups but exact envelope/target/session digests; bodyless GET/DELETE allow empty ExactRPC and record payload none, every POST records client_data. initialize requires initializing session and generation=0; initialized requires matching completed initialize; ReadySession then marks ready before tools/list. tools_list/ping/get_stream need ready but catalog may be absent; cancel requires a proved active ID held by the parser; delete permits initializing/ready. tools_call requires ready/current nonzero catalog and nonempty complete intents. server_reply requires ready, exact outstanding observed server request and parent operation/session/owner binding; it is a child native decision even with no portable ToolIntent, not a fabricated function tool. Both tools_call and data-bearing server_reply need ToolDecision; Strict denies, Review asks, Observe follows policy unless replay_barrier forces fresh user approval. Parent catalog is frozen for replies; unrelated current catalog changes cannot silently rewrite its intent. These predicates are the Store.Start kind-specific branches, not one ready/catalog predicate for all RPCs.

Inbound once rule: Receive atomically INSERTs received operation/event plus session-bound inbound key when a parsed RPC identity exists. Same key+same request digest returns original OperationID/Duplicate=true, creates no new work and cannot grant another Start; same key+different digest returns ErrConflict. IDs are type-sensitive; reused numeric ID with changed params within a live session is denied. Bind verifies Receive's request/RPC identity against exact RPC. Unclassified OFF rejection has no parsed key and no send authority. Missing observed cross-session call ID is never rescued by a random operation key: uncertain Finish and session404/reinitialization persist scope.replay_barrier=1 **before** any replacement session can start calls. Add `MarkReplayBarrier(context.Context,captureidentity.Reference,uint64,time.Time) error` to Repository, called before reinit; RegisterSession also sets it when replacing a prior session generation. Existing inbound keys protect the current session; separate stable replay keys protect proved cross-session identity. A new RPC ID alone is not a new action.
