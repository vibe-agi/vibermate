# ViberMate 0.1.38 (41) — Long Codex sessions and experimental transparent capture

- Fix long Codex sessions failing with `502 message_transform_failed` when no message transform is configured (#86). Forwarding re-encoded the whole Responses request with HTML escaping, which could grow an admitted history past the 16 MiB request limit; retrying repeated the failure. Requests are now forwarded verbatim when the model is unchanged, and encoded without HTML escaping when model mapping or a Cyber preference requires a rewrite.
- Add experimental transparent capture (#69): `vibermate run --transparent` routes an Agent and every process it starts through ViberMate without proxy variables, TCP and UDP alike. On macOS, enable **Settings → Preferences → Transparent capture on this Mac** and approve the signed network extension and network configuration; a local App is required even with `--server`. On Linux it needs unprivileged user namespaces. It is off by default and not yet release accepted; see [transparent capture](../transparent-capture.md) for known limits.
- Add capture scope (#81–#84): each Environment can list destinations that never enter ViberMate, such as localhost, the LAN, intranet names or a VPN, so they still work when the Runtime runs on a server. Edit it under **Direct from the user's computer** in the Environment editor of the App or web console. Proxy mode, Linux transparent capture and the macOS extension enforce it on the client; ViberMate neither records nor controls these connections.
- Package the macOS transparent proxy extension so it activates and starts from the notarized App: embedded frameworks are signed (#74), the extension holds the App Group of its Mach service (#79) and no longer links the App's CocoaPods frameworks (#80), and release evidence stages its executable correctly (#76).
- Update `github.com/klauspost/compress` to v1.20.2 (GO-2026-6865) and `github.com/andybalholm/brotli` to v1.2.7 (GO-2026-6888) (#87).
- `vibermate --help` and the README describe transparent capture on both platforms and where its setting is (#75, #78).

Upgrade the Desktop App, or the Runtime Server used by the CLI, then retry an affected Codex session; its history does not need to be deleted. The long-session fix was verified with regression tests at the request limit and a local replay of the failing session; it does not raise the 16 MiB limit. Build 40 was an internal test candidate and was not published.

## 中文

- 修复未配置消息转换时，长 Codex 会话仍返回 `502 message_transform_failed` 的问题（#86）。转发时整个 Responses 请求被重新编码并做 HTML 转义，可能使已接受的历史超过 16 MiB 请求上限，重试也会重复失败。现在模型不变时原样转发；需要模型映射或 Cyber 偏好改写时，编码不再做 HTML 转义。
- 新增实验性透明接管（#69）：`vibermate run --transparent` 无需代理环境变量，即可让 Agent 及其启动的所有进程经过 ViberMate，TCP 和 UDP 均覆盖。macOS 上需在 **设置 → 偏好设置 → 此 Mac 上的透明采集** 中开启，并批准已签名的网络扩展和网络配置；即使使用 `--server` 也需要本地 App。Linux 上需要非特权用户命名空间。默认关闭，尚未通过发布验收；已知限制见[透明接管](../transparent-capture.md)。
- 新增接管范围（#81–#84）：每个 Environment 可列出永不进入 ViberMate 的目标，例如 localhost、局域网、内网域名或 VPN，使 Runtime 部署在服务器上时这些目标仍可访问。可在 App 或 Web 控制台 Environment 编辑器的 **从用户电脑直连** 中设置。代理模式、Linux 透明接管和 macOS 扩展均在客户端执行；ViberMate 不记录也不控制这些连接。
- 修复 macOS 透明代理扩展的打包，使其能从公证后的 App 激活并启动：签名内嵌框架（#74）、为扩展加入其 Mach 服务所需的 App Group（#79）、扩展不再链接 App 的 CocoaPods 框架（#80），发布证据正确暂存扩展可执行文件（#76）。
- 将 `github.com/klauspost/compress` 升级到 v1.20.2（GO-2026-6865），`github.com/andybalholm/brotli` 升级到 v1.2.7（GO-2026-6888）（#87）。
- `vibermate --help` 和 README 说明两个平台上的透明接管及其设置位置（#75、#78）。

更新桌面 App 或 CLI 使用的 Runtime Server 后，可重试受影响的 Codex 会话，无需删除历史。长会话修复经过请求上限处的回归测试和失败会话的本地回放验证；不会提高 16 MiB 上限。Build 40 为内部测试候选版本，未发布。
