# ViberMate 0.1.36 (38) — Record reading and connection recovery

- Fix Web/Desktop decoding of signed content cursors, stale request details, and late responses from a previously selected run. Request details can load and continue through the current Runtime API.
- Avoid rewriting unchanged recording archives during routine retention. Preserve physical deletion/restart recovery, show the maintenance cause when recording needs a restart, and fix a validated header-only SQLite WAL transition being mistaken for changed history.
- Bound VLESS outer connection establishment across retries to 30 seconds. Retire failed TLS/REALITY setup resources while established and new streams continue on the same helper. A stalled DNS address family no longer consumes the entire target connection budget.
- Preserve Codex configuration across subcommands, support the 0.163 Cyber CLI option and original Enterprise workspace requirements, and keep ordinary native proxy fallback on the Capture route. Add exact official API Key model-capability support without extending custom-provider credential destinations.
- Include the effective default network policy and unapplied revision indicators from PR #66. Build release components with Go 1.26.10.

These shared network fixes apply to Agent CLIs including Codex and Claude. Selected exits and existing trust checks remain enforced; failed model requests are not automatically replayed. Trusted native requirements that force operating-system proxy routing are not qualified for Capture ownership.

The persistent deployed summary-only `inspection_changed` report has not been independently reproduced. This release fixes the demonstrated WAL transition and adds an inspection-phase response header for further diagnosis; it does not claim every 409 has the same cause. No storage schema change is included.

## 中文说明

- 修复网页版和桌面端对带签名游标的解析，使请求详情和后续内容页能正常读取；同时修复详情缓存过期、切换运行记录后旧请求干扰当前页面的问题。
- 没有待清理数据时不再重写归档。保留物理删除和重启恢复保证；维护失败时显示原因与恢复要求；修复合法的仅含文件头的 WAL 变化被误判为历史冲突。
- VLESS 外层连接建立与重试共用 30 秒时限，失败后回收资源，同一代理中的正常长连接和新连接继续工作。单个 DNS 地址类型查询停滞不再耗尽后续连接时间。
- 修复 Codex 子命令丢失配置，兼容 0.163 的 Cyber 参数和原始企业工作区要求；限制普通配置触发的原生代理回退，并完善官方 API Key 的模型能力适配。
- 包含 PR #66 的默认网络出口与未应用修订提示；发布组件升级到 Go 1.26.10。

网络修复沿用 Codex、Claude 等 Agent CLI 共用的代理架构。不会自动切换出口或重发模型请求。强制使用操作系统代理的原生可信要求，仍不在已验证的 Capture 接管范围内。

线上持续的 summary-only 409 尚未独立复现；本版修复已复现的 WAL 变化，并增加读取阶段诊断，不把所有 409 归为同一原因。本版不改变存储格式。
