# ViberMate 0.1.33 (35) — Account controls and local run recovery

- Capture history errors stay in the Capture records view. Confirmed traffic policy assignments remain visible, and unavailable history is not shown as zero turns.
- Account details group identity, credential dates, network exit and cyber preference. Account activation uses compact controls, and reset credits show time remaining alongside their expiration date. Manual refresh joins an existing pending read without another upstream request; background reads leave refresh icons still.
- An Agent launched locally by the updated CLI can keep running in the same process after the Desktop App restarts. The CLI reconnects with a fresh Capture using the original launch settings. Model POST requests are not automatically replayed, and required tool approvals must be granted again for the new Capture.
- Recovery requires runs started with both the updated CLI and updated Desktop App. Already-running older CLI processes need to be restarted once.

The existing [v0.1.32 backup and rollback boundary](https://github.com/vibe-agi/vibermate/blob/v0.1.32/docs/backup-and-restore.md#format-compatibility-and-rollback) continues to apply.

## 中文说明

- Capture 历史记录错误仅在对应记录视图中提示。已确认的流量策略分配保持可见，历史记录不可用不会显示为零轮对话。
- 账号详情按身份、凭据时间、网络出口和网络安全模式偏好分组。账号启用改用紧凑控件，重置券在到期日期旁显示剩余时间。手动刷新会等待同一条已在进行的读取，不重复请求上游；后台读取不会让刷新图标转动。
- 通过新版 CLI 在本机启动的 Agent，可在桌面 App 重启后继续使用原进程。CLI 使用原有启动设置重新连接，并创建新的 Capture。模型 POST 请求不会自动重放，新 Capture 所需的工具审批必须重新授予。
- 此恢复能力要求使用新版 CLI 和新版桌面 App 启动运行。已经运行中的旧版 CLI 进程需要先重启一次。

现有的 [v0.1.32 备份与回滚边界](https://github.com/vibe-agi/vibermate/blob/v0.1.32/docs/backup-and-restore.md#format-compatibility-and-rollback)继续适用。
