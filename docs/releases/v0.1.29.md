# ViberMate 0.1.29 (31) — Capture reliability and lifecycle fixes

Improves local and remote Capture startup, preserves native Codex authentication choices, and fixes connection authority, credential shutdown, and Paseo compatibility issues.

- Codex keeps its own provider, persisted login, and default destination. ViberMate no longer guesses authentication from an exported API key or injects a placeholder key; explicit Base URLs and Environment/account permissions still apply.
- Capability probes, network establishment, and default initial Run/ACP login checks allow 30 seconds and honor cancellation or an explicit shorter control timeout. Capture creation retains its 90-second budget; default heartbeat, attach, and finish operations retain 5 seconds.
- Remote login checks use the current server session's MachineID. When the default login store is absent, the complete legacy `~/.vibermate/login-sessions.json` document can migrate once; an existing default store, including an empty logout record, takes precedence. Expiry and machine binding remain enforced.
- Fixes HTTP Original Destinations through HTTPS Runtime connections, default ports, buffered CONNECT data, long paths and directories containing spaces. Launch errors distinguish network, login, Capture preparation, and capability failures with redacted, actionable diagnostics.
- `doctor` checks the control session, machine binding, explicitly selected Environment, and the proxy's credential-free CONNECT entrance without creating a Capture, contacting a model, or enrolling TLS trust. Capture creation, authorized forwarding, native launch/login, and model inference are explicitly reported as unchecked.
- Paseo accepts the current Environment catalog with tool access enabled or disabled, while preserving legacy catalog support and strict validation.
- Runtime shutdown drains admitted OAuth refreshes, retries retained credential writes before closing their transport, and reports a continuing storage failure. A persistent storage outage or abrupt process exit can still require reconnecting the account.
- Auxiliary and opaque requests keep the admitted endpoint's actual origin, path, query, and credential destination. Hold/resume probes preserve the original network access restrictions, including native MCP calls.
- Canceled cleartext forwarding and Runtime shutdown close and join upload, socket, callback, lease, and audit work, including a blocked final upload close.
- Reused HTTP/1 and HTTP/2 connections recheck live Capture authority before new operations. Revocation, credential rotation, Capture finish/expiry, and originating session/user changes withdraw affected connections and join their cleanup; idle blind and SOCKS TCP tunnels follow the same lifetime. Renewal preserves valid connections. Bytes already admitted or sent cannot be recalled.

Update both the CLI and Runtime Server to receive fixes that span their connection boundary. This release introduces no new database schema or migration; the existing supported v1-to-v2 startup upgrade and private rollback contract remain in effect. Software release does not deploy or restart a remote Runtime Server.

## 中文说明

改善本地与远程 Capture 启动，保留 Codex 原生认证选择，并修复连接权限、凭据退出清理及 Paseo 兼容问题。

- Codex 自己决定 provider、持久化登录和默认目标。ViberMate 不再根据导出的 API Key 猜测认证方式或注入占位 Key；显式 Base URL、Environment 和账号权限仍生效。
- 能力探测、网络连接建立及 Run/ACP 默认初始登录校验允许 30 秒，仍遵守取消和显式更短的控制超时。Capture 创建保持 90 秒，默认心跳、附加和退出清理保持 5 秒。
- 远程登录按服务器当前会话的 MachineID 校验。默认登录存储缺失时，可一次性迁移完整的 `~/.vibermate/login-sessions.json`；已有默认存储优先，包括退出后的空记录。过期与机器绑定检查保持有效。
- 修复 HTTPS Runtime 上的 HTTP 原始目标、默认端口、CONNECT 缓冲数据及连接清理；长路径和含空格目录可正常启动。启动诊断区分网络、登录、Capture 准备和能力失败，并提供脱敏的处理提示。
- `doctor` 实际检查控制会话、机器绑定、显式 Environment 和无凭据 CONNECT 入口，不创建 Capture、不调用模型、不自动登记 TLS 信任。Capture 创建、授权转发、原生客户端启动/登录及模型推理明确显示为「未检查」。
- Paseo 可读取工具访问开启或关闭的当前 Environment 目录，保留旧版兼容与严格校验。
- Runtime 正常退出会等待已接纳的 OAuth 刷新，在关闭传输前重试暂存的凭据写入，并报告持续存储失败。持续故障或进程突然退出仍可能需要重新连接账号。
- 辅助与不透明请求保留已接纳端点的实际 origin、路径、查询及凭据目的地；Hold 恢复探测保留原始网络访问限制，也覆盖原生 MCP。
- 明文转发取消或 Runtime 退出时，会关闭并等待上传、socket、回调、租约和审计清理，包括最终上传关闭发生阻塞的情况。
- 复用的 HTTP/1、HTTP/2 连接在新操作前重新校验 Capture 权限。撤销、凭据轮换、Capture 完成/过期及原始会话/用户变化会关闭相关连接并等待清理；空闲盲隧道与 SOCKS TCP 使用相同生命周期。有效续期保留连接；已接纳或已发送的数据无法撤回。

涉及连接两端的修复需要同时更新 CLI 和 Runtime Server。本版不新增数据库 schema 或迁移；现有受支持的 v1→v2 启动升级与私有回滚契约继续适用。发布软件不会自动部署或重启远程 Runtime Server。
