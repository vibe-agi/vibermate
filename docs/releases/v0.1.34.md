# ViberMate 0.1.34 (36) — Codex new-session compatibility

Fix a request-parser inconsistency that could reject new Codex sessions with `invalid_exchange_request` before contacting the model service. Native tool declarations within `additional_tools` now receive the same compatibility handling as top-level declarations, while their original provider request is preserved.

Tool execution still follows the selected permission policy. Strict cross-protocol validation, malformed-request checks and finite request-memory budgets remain enforced.

This release includes the local App restart recovery and account-view improvements from 0.1.33. Existing [backup and rollback boundaries](https://github.com/vibe-agi/vibermate/blob/v0.1.32/docs/backup-and-restore.md#format-compatibility-and-rollback) continue to apply.

## 中文说明

修复请求解析不一致导致的新 Codex 会话启动失败：模型请求可能在发往上游之前就被拒绝，并显示 `invalid_exchange_request`。`additional_tools` 内的原生工具声明现在与顶层声明采用相同的兼容处理，发给上游的原始请求保持完整。

工具执行仍遵循所选权限策略；跨协议转换的严格校验、无效请求检查和有限内存预算继续生效。

本版包含 0.1.33 的本地 App 重启恢复和账号界面改进。现有[备份与回滚边界](https://github.com/vibe-agi/vibermate/blob/v0.1.32/docs/backup-and-restore.md#format-compatibility-and-rollback)继续适用。
