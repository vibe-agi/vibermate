# ViberMate 0.1.22

Published 2026-10-01 at 03:25 UTC from `5131dbd` ([release](https://github.com/vibe-agi/vibermate/releases/tag/v0.1.22)). macOS App 0.1.22 (24), Runtime/CLI 0.1.22.

## Highlights

- Fix `control response exceeded 2 MiB` when opening a request carrying a large conversation history. Checkpoints no longer hydrate historical message bodies just because the request row becomes visible.
- Read history and protocol metadata in bounded pages; open large messages and text/tool-argument segments explicitly. Keep the ordinary 2 MiB control-response protection, distinguish unloaded content from omitted recording, and label copies as the loaded page only.
- Bound directory-preview reads and compressed-block decoding. The reader retains its current page and navigation positions, not every previously visited body.
- Give the Preview App its own bundle identifier and preferences domain so narrow-window testing cannot replace the live App's saved geometry or UI preferences.

## Upgrade notes

- Finish or stop active Captures before upgrading; restart the App/Server to load the new binaries. No user session is restarted automatically.
- Upgrade a remote Runtime as well as the App for large-history paging. Small legacy reads remain compatible with older Runtimes, without raising their response-size limit.
- SQLite schema revision 1, existing data and retention/recording choices are unchanged. Paging never truncates the request sent to the provider or rewrites retained evidence.
- If a previously saved window is still narrow, use **Window → Restore Recommended Size**. Existing user-selected window sizes are preserved, not forcibly reset during upgrade.
- Reads are bounded, not independent of all database costs: deep history seeks traverse ancestry metadata. Explicitly opening a large message verifies that one message under the existing 32 MiB retained-record bound before returning a segment.
