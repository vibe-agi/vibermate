# ViberMate 0.1.23

macOS App 0.1.23 (25), Runtime/CLI 0.1.23.

## Highlights

- Extend the default desktop control session lifetime from 12 hours to 10 days.
- Renew control sessions independently of dashboard polling, including while the window is hidden. Retry a lost renewal response with the same idempotency key; an in-flight read using a retired token cannot invalidate the renewed session. Writes are not automatically replayed.
- Avoid duplicate request-only recording finalization when an exchange is canceled or fails before receiving a response. Genuine missing response content remains visible; this does not backfill historical gaps.
- Add the experimental open-source Paseo conversation profile picker, shared by desktop, web and mobile clients, with persistent per-Agent Environment choices. Add the permission-filtered `vibermate profiles --json` catalog and cancelable launcher preparation. See [Paseo integration](../paseo-integration.md).

## Upgrade notes

- Finish or stop active Captures before upgrading, then restart the App/Server to load the new binaries. This release does not restart user sessions automatically.
- Already-issued 12-hour control sessions are not retroactively extended. The new lifetime applies to sessions issued or renewed by the upgraded desktop Runtime.
- A hidden window can renew while the computer is awake and the App is running. System sleep suspends timers; a session that has already expired or been revoked still requires reconnection.
- SQLite schema revision 1 and retained request/response evidence are unchanged. Existing recording warnings and genuine historical gaps are not silently cleared.
- Paseo requires plugin-capable 0.11.0-beta.3 and a ViberMate 0.1.23+ CLI/Runtime on its daemon host. Physical iOS/Android and live Paseo desktop acceptance remain separate from deterministic SDK/compiler checks.
