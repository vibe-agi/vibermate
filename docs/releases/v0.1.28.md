# ViberMate 0.1.28 (30) — Control-plane performance

Reduces idle and statistics-view load on shared Web and App control paths without changing Capture recording policy, trust, or schema.

- Capture statistics learn retained bodies from a launch-summary EXISTS flag instead of `conversations(200)` identity enrichment.
- Conversation identity reindex no longer re-arms its 10k budget while the Capture activity watermark is idle or a repair pass is still incomplete.
- Exchange summary aggregation projects only lifecycle columns needed for `GROUP BY`.
- Workbench 5s polls outside Captures/Settings/Usage refresh `/status` only; inventory reloads on section change.
- Usage snapshot invalidation uses `MAX(sequence)`, soonest expiry, and retention caps instead of `COUNT(*)`.
- Stats-only overview omits NativeToolReader; ClearEvidence checkpoints and VACUUMs after a successful wipe so the file shrinks.
- Running Captures that opened before the first retained body re-probe summary so the directory remounts when bodies appear.
- Includes prior Codex native signer / codesign warm-path reliability work already present on this line.

No new database migration. Existing accounts, history and trust material are preserved.

## 中文说明

优化共享控制面在空闲与「仅统计」视图下的读写成本，不改变录制策略、信任模型或数据库 schema。

- 统计态用 summary 的正文存在标志，不再靠拉 200 条会话目录探正文。
- 会话身份索引在水位未前进或修复未完成时不会错误空闲短路。
- 请求汇总只投影聚合所需列；非 Captures/Settings/Usage 的 5 秒轮询只打 `/status`。
- 用量快照不再对观察表做 `COUNT(*)`；清空证据后 checkpoint + VACUUM，磁盘真正回落。
- 运行中的 Capture 若之后出现正文，会重新探测并回到会话目录。

无数据库迁移；保留账号、历史与信任材料。
