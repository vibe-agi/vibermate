# ViberMate 0.1.31 (33) — managed client authentication

Users without a local Codex login can explicitly use an Environment's managed model-service account:

```sh
vibermate run --env work --managed-auth -- codex
vibermate run --env work --server https://your-runtime.example --managed-auth -- codex
```

- The opt-in `--managed-auth` option supports recognized Codex and Claude clients. It requires an explicit Environment with an existing protected, managed destination. Ordinary launches keep their existing login behavior.
- Codex receives a per-invocation Responses provider. Upstream credentials stay on the Runtime; each Capture authenticates separately to the proxy. Local login files, configuration and history are preserved.
- Existing `openai` conversations can resume by UUID with the flag: `vibermate run --env work --managed-auth -- codex resume <UUID>`. Codex's picker filters by provider; `--all` removes only directory filtering. Native thread ownership and model selection still apply.
- Claude uses `vibermate run --env work --managed-auth -- claude`, with the existing managed gateway-token path. Conflicting provider settings or an unavailable managed destination produce localized diagnostics before child launch, with Capture cleanup.
- Daybreak Blue/Red preferences use Standard only when the same final model explicitly advertises Standard and does not advertise the preferred mode. Missing or failed discovery still reports unavailable; the saved preference, account and model are preserved.

Native Codex 0.163.0 acceptance uses isolated homes and synthetic loopback responses, including fresh interactive startup and UUID resume. Model routing does not replace Codex's native local status, OAuth-only features, Cloud or connector login.

The storage format remains monolithic runtime revision 3, with the existing upgrade and rollback boundary. This staged release does not include the separate recording-storage isolation work or deploy a remote Runtime Server.

## 中文说明

没有本地 Codex 账号时，可以显式添加 `--managed-auth`，使用流量策略中已配置的受管理账号启动：

```sh
vibermate run --env nixiang --server https://ai.appsflyme.com --managed-auth -- codex
```

该选项支持已识别的 Codex 和 Claude 客户端，要求明确指定流量策略，且策略已经包含对应的受管理目标。上游密钥或 OAuth 凭据保留在 Runtime，不会交给子进程；本地登录文件、配置和历史记录保持由客户端管理。

已有 Codex 会话可以通过 `codex resume <UUID>` 配合该选项继续。原生会话选择器按 provider 筛选，`--all` 只取消目录筛选；原生会话所有权和模型选择规则仍然适用。Claude 使用同一个选项及现有托管网关凭据路径。

同时包含 PR #54 的同模型模式兼容：Blue/Red 不可用时，只有最终同一模型明确支持 Standard 才使用 Standard；发现失败或未知能力不会触发回退，保存的偏好、账号及模型不变。

本版沿用 runtime 第 3 版单体数据格式及原有升级、回滚边界。记录存储解耦另行发布；软件发布不会自动更新或重启远端服务器。
