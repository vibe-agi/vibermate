# ViberMate 0.1.32 (34) — recording isolation

Agent traffic and required control state are separated from optional recording. Slow or unavailable history storage can leave gaps in request/response bodies, conversation history, usage and traffic records; recording queues have finite memory and capacity. The workbench reports known loss and uncertain completion separately.

- Account configuration, permissions, approvals and native tool execution/replay state remain required state. Missing optional tool-result content cannot authorize a second execution.
- Privacy changes commit their required intent before acknowledgement. Background cleanup and its completion certificate remain visible even when optional statistics are unavailable.
- Capture details refresh before an explicit refresh completes, while initial readiness and approval discovery progress independently. Finished Captures with observed traffic are no longer shown as incomplete launches merely because optional assignment details are missing.
- Existing published Runtime data transitions through guarded storage preparation with an independent private snapshot. The original archive is retained; required control and current optional recordings use separate roles. Public backups validate every declared role and disclose missing or unverified history.

Older releases cannot open the new split layout or its v2 public backups. Rollback requires restoring the preserved old-format private snapshot into a new directory. See the [backup and rollback boundary](https://github.com/vibe-agi/vibermate/blob/v0.1.32/docs/backup-and-restore.md#format-compatibility-and-rollback).

This release also includes the explicit managed client authentication introduced in 0.1.31. Publishing software does not deploy or restart a remote Runtime Server.

## 中文说明

Agent 流量和必要控制状态与记录存储分离。历史存储缓慢或不可用时，请求/响应正文、会话展示、用量和流量记录可能缺失；记录队列的内存与容量都有上限。工作台分别显示已知丢失和完成情况未知的记录。

- 账号配置、权限、审批，以及原生工具的执行和防重放状态仍需可靠保存。缺少结果展示内容不会允许工具再次执行。
- 隐私变更先可靠提交必要操作，再返回确认。后台清理及其完成凭证保持可见，独立于可选统计读取。
- 显式刷新会等待当前详情更新，初始化和审批发现保持独立。已经观察到流量的已结束 Capture，不会仅因缺少分配详情而显示“启动未完成”。
- 已发布的数据格式通过受保护的准备流程转换，并保留独立私有快照和原始档案。必要控制状态与当前记录分别存储；公开备份会校验声明的角色，并明确标出缺失或未完整验证的历史。

旧版本不能读取新的分离布局及其 v2 公开备份。回滚需要将保留的旧格式私有快照恢复到新目录。请参阅[备份与回滚边界](https://github.com/vibe-agi/vibermate/blob/v0.1.32/docs/backup-and-restore.md#format-compatibility-and-rollback)。

本版同时包含 0.1.31 引入的显式托管客户端认证。软件发布不会自动部署或重启远端 Runtime Server。
