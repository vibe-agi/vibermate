## 中文

ViberMate 0.1.15 改进 Codex 原生协议兼容性、账号管理和用量报表。

- 修复长历史会话在远程压缩前被本地扩展数量限制拒绝的问题；保留原生历史与加密状态，继续执行每条消息、总字节数和响应侧的安全限制。
- 修复流式进度、非终止错误通知和完成事件的转发，以及压缩流关闭时与解码读取冲突造成的卡住；保留工具审批边界，明确区分上游失败、传输失败和未完成响应。
- 保留受控的原生响应元数据和错误语义；按账号及路由隔离续接状态，修复 HTTP/2 响应头超时的起算点。
- 修复退出后的终端模式恢复、运行记录时间及排序跳变，以及刷新时请求记录页意外切回概览的问题。
- 修复 Codex 历史消息作者与原生会话身份冲突造成的持续详情 503；旧索引可后台恢复，读取失败不再误显示为零请求或未绑定策略。
- 精简账号列表与展开详情，统一已用额度和重置券计数，减少重复操作并对齐搜索、排序控件。
- 新增 Runtime 全局用量采集设置：正文不录制时也可独立统计，本地 App、Web 和运行用户按各自权限查看。已有安装需显式开启；未采集的历史不会回填。
- 新增按 models.dev 参考单价计算的 API 等价费用、计价覆盖和分组趋势；可见用量页面每 5 秒刷新，并显示手动刷新状态和错误。
- 用量明细支持逐层展开：策略/上游账号/来源查看模型构成，模型查看调用者；新增调用者和 Git 项目维度，按仓库、启动分支、调用者、模型核对小计与费用。使用千位分隔、统一 USD 列与独立总计。

Git 分支为新启动运行的启动时快照，不追踪运行中切分支，也不推测历史缺失值。调用者优先使用已认证 Runtime 用户；本机用户名是启动器报告的显示信息，不作为认证身份。不会读取 Git 远端 URL、提交作者或仓库内容。

费用是按当前参考单价计算的美元估算，不是包月扣费或上游账单；缺失用量、未定价模型和不支持的收费模式不会被当作零成本。

Codex 原会话仍被其他后端占用时，遵循客户端原生的重试或显式分叉选择，不强制解锁，也不自动分叉。分叉会创建新的会话 ID。

macOS 14+（Apple silicon / Intel）：

```sh
brew update
brew install --cask vibe-agi/tap/vibermate
# 已安装：brew upgrade --cask vibe-agi/tap/vibermate
```

Linux x86_64 / arm64 压缩包包含 Server、CLI 和 Web 工作台。下载后请校验对应的 `SHA256SUMS` 或 `SHA256SUMS-linux`。

## English

ViberMate 0.1.15 improves native Codex compatibility, account management, and usage reporting.

- Fix local rejection of long-history remote compaction. Preserve native history and encrypted state while retaining per-message, aggregate-byte, and response limits.
- Correct streaming progress, non-terminal error notifications, and completion handling without bypassing tool approval. Prevent compressed stream shutdown from racing active decoder reads or hanging. Distinguish provider failures, transport failures, and incomplete responses.
- Preserve controlled native response metadata and error semantics, isolate continuation state by account and route, and start the HTTP/2 response-header timeout after request upload.
- Restore terminal modes after child exit; stabilize Capture activity times, ordering, and the selected requests view during refresh.
- Repair persistent Capture detail 503s caused by historical message authors conflicting with native Codex session identity. Old projections recover in the background; failed reads are no longer shown as zero requests or missing policies.
- Simplify account rows and details, clarify used quota and reset-credit counts, and align search and sort controls.
- Collect body-free usage independently of content recording through an explicit Runtime-wide setting. App, Web, and authenticated Runtime Users share permission-scoped reports. Existing installations must opt in; uncollected history is not backfilled.
- Estimate API-equivalent USD costs using current models.dev reference prices, with pricing coverage and grouped trends. Visible usage pages refresh every five seconds and expose manual-refresh progress and errors.
- Expand usage breakdowns from policies, upstream accounts and sources to models, or from models to callers. New caller and Git project views drill down by repository, branch at launch, caller and model, with subtotal rows, full numeric formatting and a separate total.

Git attribution is a launch-time snapshot for newly launched runs, not a history of branch switches. Missing metadata remains unknown. Authenticated Runtime users take precedence over launcher-reported local labels; local labels are not authentication. No Git remote URLs, commit authors or repository contents are read.

Estimated costs are not subscription charges or provider bills. Missing usage, unpriced models, and unsupported charging modes are not treated as free usage.

When another Codex backend owns the original session, use the client's native retry or explicit fork options. ViberMate does not force-unlock or automatically fork sessions; a fork has a new session ID.
