# ViberMate 0.1.39 (42) — A redesigned workbench, and conversations that ride out storage trouble

## Conversations keep working when storage struggles

- A slow settings read no longer ends running conversations (#90).
- Recording pauses by itself when the data volume is nearly full and resumes when space returns; conversations keep working either way (#91).
- If storage fails while a request is re-checked or a connection is opened, the agent gets a retryable `503` with `Retry-After` instead of a `403` that looks like a revoked credential, and continues once storage answers (#96, #108). Connection checks read on connections of their own, so a long write or screen read cannot hold them up. A SOCKS UDP association rides out up to 30 seconds of storage trouble; a real rejection still closes it at once.

## A workbench organised around the path a request takes

The sidebar now follows a request: **Watch** (Sessions, Approvals, Usage and cost) and **Control** (Routing, Accounts, Scripts, Network exits), on a framed sheet with a new palette, light first with a graphite dark mode (#89).

- **Sessions** open on a ledger of every request in the session, with filters for changed, blocked and failed requests, what each script did, and the full request one click away (#97). A request a script changed can be compared before and after (#116). English calls a run a session (#102).
- **Approvals** shows what was decided recently and by whom (#99), and lists tool questions from every session, not only the one you have open (#118).
- **Usage and cost** has one status line, four headline figures, a per-day chart and "Where it went" by project, routing set, account, model, source or caller (#111).
- **Routing** (formerly Traffic policies; one policy is now a *routing set*) reads each path left to right: agent, audit and scripts, where it is sent and whether it is translated, the account, and the network exit it leaves through (#114, #115). It lists the sessions running on it now (#117).
- **Scripts** (formerly Script library) show which routing sets run them and what they did to the last week's requests (#104, #105).
- **Accounts** are grouped by the service they belong to (#103, #110).
- **Network exits** are their own destination with a default-exit band, a table of exits, and which routing sets and accounts use each (#101, #106, #112).
- **Settings** lists its sections beside the content on wide windows (#113).

## Scripts

- Every request records what each message script did to it, and a script can refuse a request with `runtime.block` (#92, #94).

## Security

- The readable request view also hides JSON Web Tokens, GitHub, Slack, Google and AWS keys, and ViberMate's own proxy credentials (#109). Raw recordings still keep bodies exactly as sent; only credential header values are removed.
- All runtime artifacts are built with Go 1.26.11 (#93).

## Upgrading

Settings, accounts and credentials are kept. The recording database gains one column on first start, and existing recordings are kept. The Runtime adds two read endpoints (`environment` on `GET /api/v1/captures`, and `GET /api/v1/native-tools/approvals`); an App talking to an older Runtime falls back to its previous behaviour.

## 中文

### 存储出问题时，对话照常进行

- 读取设置变慢时，不再中断进行中的对话（#90）。
- 数据卷快满时自动暂停录制，空间恢复后继续；对话始终不受影响（#91）。
- 重新校验请求或建立连接时若存储失败，Agent 收到可重试的 `503`（带 `Retry-After`），而不是看起来像凭据被吊销的 `403`，存储恢复后继续（#96、#108）。连接校验使用独立的读连接，长时间写入或界面读取不会拖住它。SOCKS UDP 关联可容忍最长 30 秒的存储故障；真正的拒绝仍会立即关闭。

### 按请求路径组织的工作台

侧栏按请求的路径排列：**观察**（运行记录、审批、用量与费用）和 **控制**（流量策略、账号、脚本库、网络出口），采用带框的版面与新配色，默认浅色，并保留石墨深色模式（#89）。

- **运行记录** 打开即是该会话全部请求的台账，可筛选已改写、已拦截和失败的请求，查看每个脚本做了什么，一键打开完整请求（#97）。被脚本改写的请求可以比较前后差异（#116）。
- **审批** 显示最近的决定及由谁做出（#99），并列出所有会话中待回答的工具问题，而不只是当前打开的会话（#118）。
- **用量与费用**：一行状态、四个核心数字、每日图表，以及按项目、流量策略、账号、模型、来源或调用者划分的"用量去向"（#111）。
- **流量策略** 从左到右展示每条路径：智能体、审计与脚本、发送到哪里以及是否转换协议、使用的账号、以及离开时经过的网络出口（#115），并列出正在使用它的会话（#117）。
- **脚本库** 显示哪些流量策略在运行某个脚本，以及它对最近一周请求做了什么（#104、#105）。
- **账号** 按所属服务分组（#103、#110）。
- **网络出口** 成为独立页面，包含默认出口、出口列表，以及每个出口被哪些流量策略和账号使用（#101、#106、#112）。
- **设置** 在宽窗口中把分区列在内容旁边（#113）。

### 脚本

- 每个请求都会记录每个消息脚本对它做了什么，脚本可以用 `runtime.block` 拒绝请求（#92、#94）。

### 安全

- 可读的请求视图还会隐藏 JSON Web Token、GitHub、Slack、Google 和 AWS 密钥，以及 ViberMate 自己的代理凭据（#109）。原始录制仍按原样保存正文，只移除凭证头的值。
- 所有运行时产物使用 Go 1.26.11 构建（#93）。

### 升级

设置、账号和凭据都会保留。录制数据库在首次启动时增加一列，已有录制会保留。Runtime 新增两个只读接口（`GET /api/v1/captures` 中的 `environment`，以及 `GET /api/v1/native-tools/approvals`）；连接旧版 Runtime 的 App 会回退到原有行为。
