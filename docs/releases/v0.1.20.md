# ViberMate 0.1.20

Release candidate: macOS App 0.1.20 (22), Runtime/CLI 0.1.20.

## Highlights

- Fix request previews truncated at whitespace. An invalid optional preview no longer makes an entire Capture detail page unreadable; retained requests remain accessible.
- Expand Codex Responses compatibility for native reasoning/text controls, tool-result history and empty terminal output. Align response stop reasons across Runtime and Web, and add shared wire-contract fixtures plus current Codex client checks on macOS/Linux.
- Check required local macOS Codex root trust before launch and provide an actionable error when interception cannot work.
- Open reset-credit details from the voucher count. Available credits expiring within three days are highlighted. Selection does not consume a credit: one confirmation combines weekly usage, a sooner-expiring alternative and a natural quota reset within three hours. Expired/used credits cannot be selected. Credit balances display two decimal places.
- Combine traffic-policy account scope and manual/script selection. Same-origin, same-protocol routes can keep the original request account without injecting managed credentials. Manual account changes apply to subsequent requests, not requests already in flight. Scripts still see only their explicitly scoped managed accounts.
- Preserve account-history permission when editing only the scope of the same fixed account. Changing account identity or switching away from a fixed account revokes that permission.
- Keep usage breakdown height stable when regrouping. Explicit refresh retains the current level and page (or the last remaining page if the result shrinks).
- New Runtime databases enable body-free usage collection with 365-day retention. Existing collection choices remain unchanged; body recording and account-history access are separate permissions. Account refresh and usage switches use the same compact sizing.
- Add **Settings → Access & launch → Deploy with your own domain**. It generates native commands or settings for the existing public Docker template after explicit CA terms acceptance. It does not execute commands or request a certificate. Server HTTPS status, domain and expiry are visible without expanding technical details.
- Tighten PROXY protocol/IP-allowlist handling and active-connection revalidation without blocking genuine ACME challenge connections.

- 修复预览截断后末尾空格导致的 `requestPreview is invalid`；单条可选预览异常不再影响整个运行详情页，也无需删除旧记录。
- 补齐 Codex Responses 的原生推理/文本配置、工具结果历史、空终态及前后端停止原因兼容，并增加跨语言协议样例和 macOS/Linux 当前 Codex 客户端测试。
- macOS 本地 Codex 启动前检查必要的根证书信任，缺失时明确提示。
- 点击券数量查看明细并选券；三日内到期标红。周用量、非最早到期券、三小时内自然重置的风险合并为一次确认；仅选择或查看不会消耗券。已过期/已使用的券不能选择，积分保留两位小数。
- 账号范围与选择方式合并。同源、同协议路由可以选择“原始请求账号 · 不替换凭证”；手动切换从下一请求生效，已发出的请求不变。脚本候选仍严格限定在策略账号范围内。
- 仅修改同一个固定账号的候选范围不再清除历史用量授权；更换账号身份或改用非固定模式则撤销授权。
- 统计切换分组时保持表格高度，刷新保留当前层级和页码；结果页数减少时停在最后可用页。
- 新数据库默认开启无正文用量采集并保留 365 天，已有设置不变；正文记录和账号历史授权仍然独立。两处开关统一缩小。
- 增加自有域名部署向导和清晰的服务器 HTTPS 状态。向导只生成命令/配置，不更改当前服务、不申请证书；首次签发不可访问时提供 DNS、443 和日志排查步骤。
- 加固 PROXY protocol/IP 白名单与活动连接复查，保留正常 ACME 验证通道。

## Upgrade and verification boundary

- This release does not change SQLite schema revision 1 or delete existing data. Back up the Runtime offline before upgrading. Older releases do not understand the new original-account policy mode or all newly retained response shapes; use a pre-upgrade backup if a downgrade is required.
- Update/restart the App or deployed Server to load the new binaries. Saving the usage-collection switch itself does not require a restart and does not backfill disabled periods.
- Pure tab switching alone did not reproduce the reported history-checkbox loss. The related scope-edit reset is fixed, and tab/content-setting preservation has regression coverage.
- Public ACME issuance/renewal requires a real domain and reachable validation ports. Automated tests use synthetic certificates; they are not a claim of production-domain acceptance.
- Reset-credit tests use synthetic accounts only. No real credit was consumed for this release.
