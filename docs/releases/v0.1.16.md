## 中文

ViberMate 0.1.16 统一账号出口、启动上下文与完整用量统计，并改进长时间运行的可靠性。

- 账号可选择已有网络出口方案，优先于流量策略；模型调用和已支持的账号管理操作使用相同规则。方案失败会明确报错，不静默改成直连。
- OAuth 自动刷新改为显式开关：新导入默认关闭，OAuth 登录创建默认开启，替换凭据保留已选设置。桌面账号表格只显示一个“自动刷新”列头，行内为紧凑开关；窄屏保留局部标签。
- 可用账号按相同主额度窗口的重置时间正序排列；显示紧凑倒计时、独立窗口用量及 70%／90% 警示色。增加账号组刷新，统一启用按钮尺寸，套餐标签移至图标下方。原“试跑”改为高级配置检查，不代表上游连通性测试。
- 普通 Run 与 ACP 在原有启动请求中统一上报上下文。对可明确识别的 Git origin，在本机净化后形成稳定项目身份，使同一仓库的不同克隆可归并；无法可靠识别时保留本机克隆身份。不会联系 Git 远端、上传凭据或读取提交作者及仓库正文。
- 项目报表按“项目 → 调用者 → 模型”下钻，分支为启动时快照；没有证据的历史记录不补归属。本机用户名仅用于显示，不能代替已认证 Runtime 身份。
- 运行概览使用完整请求汇总，可切换本次运行与客户端会话；无正文也能查看状态、Token、API 等价费用及异常构成，不再把已加载的 100 条当作总量。
- 汇总、趋势与明细分页分离，移除 100,000 条统计截断；按需读取下钻，保留逐请求精确计价、未知值及费用下限。报表使用独立只读连接，后台到期清理分批提交并支持预算中断后续清。
- 可选正文／活动／用量记录失败不会单独撤销代理就绪状态；核心出口审计失败仍会停止代理，并在 App、Web 和 CLI 中显示首个故障原因。
- 合盖休眠或临时断网后，启动器重试监督连接并允许原监督者续租，不再因一次心跳失败立即停止 Agent。明确撤权、结束或删除仍会终止监督；已经断开的上游流仍需客户端重试。

### 已有数据：升级前先停止并转换

运行时只支持当前 v1 结构，不自动迁移旧库。已有 0.1.15 数据需先退出 App、Runtime 和托管 Agent，使用本版本的 [离线转换工具](https://github.com/vibe-agi/vibermate/tree/v0.1.16/tool/convert-v1) 完整备份并转换到独立目录，验证后再切换。原目录保持不变；不要直接让新 App 打开旧库，也不要把新库交给旧 App。

转换保留账号引用、权限、统计设置和已保存数据；系统 Keychain 保持原位置，不导出。私有备份包含敏感数据，不能公开上传。升级并不启用原先关闭的用量采集，也不回填未采集历史。

API 等价费用为参考单价估算，不是包月扣费或上游账单。

## English

ViberMate 0.1.16 unifies account egress, launch context, and complete usage reporting, with reliability improvements for long-running Agents.

- Select an existing network egress plan per account. It takes precedence over the traffic policy for model calls and supported account operations; a failed plan never silently falls back to direct access.
- Make OAuth auto refresh explicit: new imports default off, OAuth-created accounts default on, and credential replacement preserves the selection. Desktop rows share one compact Auto refresh column; narrow cards retain local labels.
- Order comparable quota windows by reset time, soonest first. Show compact countdowns, separate quota windows, 70%/90% warning colors, group refresh, equally sized activation controls, and plan badges below account icons. Configuration checks are advanced static diagnostics, not connectivity tests.
- Report Run and ACP context through one launch request. Locally sanitized, unambiguous Git origins identify shared repositories across clones; otherwise identity remains local to the clone. No remote connection, credential upload, author lookup, or repository-content read is performed.
- Drill down from project to caller to model, with branch-at-launch attribution. Missing historical identity stays unknown, and local display names never substitute for authenticated Runtime users.
- Show complete request summaries for the current run or client session even without recorded bodies. Request pagination no longer limits totals to the loaded page.
- Separate totals, trends, and paginated breakdowns; remove the 100,000-observation cutoff while preserving per-request pricing precision and unknown/lower-bound semantics. Bounded read-only connections isolate reports; expired-record maintenance commits batches and resumes after its time budget.
- Keep optional recording failures separate from proxy readiness. Core egress-audit failure still stops forwarding and exposes the first failure consistently in App, Web, and CLI.
- Reconnect supervision after sleep or temporary network loss instead of stopping an Agent after one failed heartbeat. Only the original supervisor may renew its expired lease; revocation and finished/deleted runs remain terminal. An interrupted provider stream still requires client retry.

### Existing data requires an offline conversion before upgrade

The Runtime accepts only the current v1 structure and never migrates old databases on startup. Stop the App, Runtime, and managed Agents, then use this version's [offline conversion tool](https://github.com/vibe-agi/vibermate/tree/v0.1.16/tool/convert-v1) to create a complete private backup and a separate verified target. Keep the original directory unchanged, and coordinate the data-directory switch before launching the new App. Never open the new database with an older App.

Account references, permissions, collection settings, and retained records are preserved. System Keychain credentials stay on the original Mac and are not exported. Backups contain sensitive data and must remain private. Conversion does not enable previously disabled usage collection or invent missing history.

API-equivalent costs are reference-price estimates, not subscription charges or provider bills.
