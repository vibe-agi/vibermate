# ViberMate 0.1.17

Published 2026-09-29 from `7ac39f0` ([release](https://github.com/vibe-agi/vibermate/releases/tag/v0.1.17)).

ViberMate 0.1.17 replaces the withdrawn 0.1.14–0.1.16 releases.

> **Upgrading:** 0.1.17 cannot open data created by 0.1.16 or earlier, and there is no migration. Quit ViberMate, move `~/Library/Application Support/io.vibermate.desktop` (Linux Server: your `--data-dir`) somewhere else to keep it, then start 0.1.17 with empty data. The App explains this if it finds an old folder; nothing is modified.

## Highlights

**Protocol correctness**
- Every JSON request, response and SSE event rejects keys that collide under case folding, so ViberMate and the client always read the same fields. This closes a tool-approval bypass.
- Same-dialect forwarding accepts the full OpenAI Responses and Anthropic Messages surface instead of a closed allowlist. That covers string `input`, typeless messages, unknown items, tools, `tool_choice`, `include` and content parts.
- Upstream output that ViberMate does not model is treated as an unproven action and decided by the traffic policy: Observe allows it, Review asks, Strict refuses.
- `incomplete` responses keep their reason, and Anthropic `ping` counts as liveness.

**Security**
- Unicode host spellings can no longer bypass deny rules. The proxy dials exactly the host that policy and audit evaluated.
- New Runtime Users have no traffic-policy grants until the Owner grants them. "All policies" is an explicit choice.
- Member devices accept only agent-behaviour variables (models, timeouts, output limits, telemetry switches) from a remote Server. Variables such as `LD_PRELOAD` and `NODE_OPTIONS` are refused.
- Replacing Codex OAuth credentials no longer discards a newer rotation.
- Private PKIs that present only an intermediate chain are pinned correctly.
- Built with Go 1.26.8.

**Reliability**
- A failed audit write no longer stops the Runtime. The record is retried, new outbound traffic waits, and service resumes automatically.
- Cleanup and maintenance run in bounded batches.
- One conflicting Codex subagent identity no longer stops conversation indexing.

**Workbench**
- Route account sets show the real reason an account is unavailable.
- Usage report paging and drill-down are stable, and errors can be retried.
- The quota countdown keeps updating while the window is unfocused.
- Report cells are labelled for screen readers.

## 中文说明

ViberMate 0.1.17 取代已撤下的 0.1.14–0.1.16。

> **升级须知：** 0.1.17 无法打开 0.1.16 及更早版本创建的数据，也不提供迁移。请退出 ViberMate，把 `~/Library/Application Support/io.vibermate.desktop`（Linux Server 为你的 `--data-dir`）移到别处保留，再用空数据启动 0.1.17。App 检测到旧目录时会给出说明，不会修改其中任何内容。

- **协议：** 每个请求、响应和 SSE 事件都会拒绝大小写折叠后重名的键，修复了工具审批绕过。同方言转发不再拒绝未建模的字段。上游未建模的输出由流量策略决定：观察放行，审查询问，严格拒绝。
- **安全：** Unicode 主机名不能再绕过拒绝规则。新 Runtime User 默认没有任何授权。远程 Server 只能向成员设备下发 Agent 行为类环境变量。Codex OAuth 凭据替换不再丢失新的轮换。使用 Go 1.26.8 构建。
- **可靠性：** 审计写入失败时会保留并重试，写入后自动恢复。清理任务分批执行。子代理身份冲突不再中止会话索引。
- **工作台：** 报表翻页与下钻更稳定，出错可重试。窗口失焦时额度倒计时继续更新。报表支持读屏。
