## 中文

ViberMate 0.1.11 完成了 App、本机 Web、容器 Web 与团队服务端部署的统一接入体验，并把“访问 ViberMate 服务端”和“信任 ViberMate 代理 CA”拆成两个清晰的安全边界。

- 支持四种明确的服务端入口：可信本机/内网 HTTP、ViberMate 私有 CA HTTPS、自动公网 HTTPS，以及运维方提供的证书文件。
- 私有 CA 模式可为域名、局域网主机名或 IP 生成服务端证书；没有公网域名时，可以使用 IP 证书，或在客户端 `/etc/hosts` 中绑定自定义主机名后访问。
- 自动 HTTPS 模式由 ViberMate 申请并续期公网证书；自带证书模式适配反向代理、已有域名和团队证书体系。
- App 与 Web 的设置按任务重新组织：先选择部署方式，再展示唯一需要完成的命令、地址、证书下载与验证步骤；账号登录、服务端身份和 AI 流量代理信任不再混在一起。
- CLI 登录会记录服务端身份和连接配置，后续运行复用已验证的连接；接入协议保持 `vibermate-server-access-v1`，没有引入未发布的 v2/v3。
- 修复账号替换和消息脚本下的请求头、Unicode、SSE 与 HTTP/2 转发边界，并增强 `provider_transport_failed` 的诊断证据。
- 提供本机、Docker Compose、私有 HTTPS、团队 HTTPS 和公网 HTTPS 的可复制配置与操作文档。

这次不包含 ACP 支持；ACP 仍在独立开发分支中，不会混入本次稳定发布。

### 使用边界

- HTTP 只适合回环地址或可信私网；跨不可信网络请使用 HTTPS。
- 私有 CA HTTPS 需要每台客户端显式信任导出的 ViberMate Root CA，并确保访问地址包含在证书的 DNS/IP SAN 中。
- 自动公网 HTTPS 需要域名正确解析到服务器，并允许证书颁发机构从公网访问所需端口；发布测试使用本地 ACME 测试环境验证了完整申请与续期流程，真实公网 DNS/防火墙仍由部署方负责。

macOS 14+（Apple silicon / Intel）安装：

```sh
brew update
brew install --cask vibe-agi/tap/vibermate
```

Linux x86_64 / arm64 压缩包包含 Server、CLI 和 Web 工作台。下载后请校验对应的 SHA256SUMS 文件。

## English

ViberMate 0.1.11 unifies onboarding across the macOS App, native Web server, container Web deployments, and team-hosted runtimes. It also separates the server-identity trust boundary from the AI proxy CA trust boundary.

- Choose one explicit server entry mode: trusted local/private HTTP, ViberMate private-CA HTTPS, automatic public HTTPS, or operator-provided certificate files.
- Private-CA mode can issue a server certificate for DNS names, private hostnames, or IP addresses. A deployment without public DNS can use an IP certificate or map a chosen hostname in each client's `/etc/hosts` file.
- Automatic HTTPS obtains and renews public certificates. Operator-certificate mode fits reverse proxies, existing domains, and team PKI.
- App and Web settings are organized around setup tasks and show only the commands, URLs, certificate download, and verification steps relevant to the selected deployment.
- CLI login retains verified server identity and connection settings for later runs. The access protocol remains `vibermate-server-access-v1`; no unpublished v2/v3 schema is introduced.
- Harden request-header, Unicode, SSE, and HTTP/2 forwarding around account replacement and message transforms, with stronger evidence for diagnosing `provider_transport_failed`.
- Add reproducible documentation and smoke coverage for native, Compose, private HTTPS, team HTTPS, and public HTTPS deployments.

ACP support is not part of this release. It remains isolated on its development branch.

### Operational boundaries

- Use HTTP only on loopback or a trusted private network. Use HTTPS across untrusted networks.
- Private-CA HTTPS requires every client to trust the exported ViberMate Root CA, and the URL must match a DNS/IP SAN in the server certificate.
- Automatic public HTTPS requires correct public DNS and reachable validation ports. The release suite verifies issuance and renewal against a local ACME test service; production DNS and firewall readiness remain operator responsibilities.

Install on macOS 14+ (Apple silicon / Intel):

```sh
brew update
brew install --cask vibe-agi/tap/vibermate
```

Linux x86_64 / arm64 archives include the Server, CLI, and Web workbench. Verify downloads against the corresponding SHA256SUMS file.
