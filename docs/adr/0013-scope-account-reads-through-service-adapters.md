# Scope account reads through service adapters

Account-related control reads must follow the account that actually supplies a request without treating every CLI control endpoint as managed traffic. We distinguish client-native identity capability (`clientadapter` / launcher) from an upstream service's declared operations (`upstreamservice`). The latter supplies pure contracts and safe projections to the existing executable `operationcatalog`; it has no credentials, account selection, persistence, or network authority. Adding a service does not require a handler path table or another OAuth manager.

`accountoperation.Reader` is the shared execution boundary for two explicit scopes: an immutable Capture request plan and an owner-authorized account inspection. Capture reads require exactly one candidate route and its fixed account, then recheck the account link and endpoint authority. Ambiguous routes and JavaScript selectors fail closed before a credential is acquired; the query never reruns a Turn selector or guesses a process-wide last account. An owner can inspect an unlinked account without granting any Capture access. Both entry points use the same pre-lease OAuth preparation, credential epoch, final authentication injection, Offline Hold, strict transport and body-free egress audit as other runtime work.

The first supported service operations are exactly `GET /backend-api/wham/usage` and `GET /backend-api/wham/profiles/me` on the supported ChatGPT origin. Neither accepts a body or arbitrary query parameters. History additionally requires the route's explicit `allowAccountHistory` permission, default off and revisioned separately from the account selection policy. The editor clears that permission when selecting a different account. These reads create no Exchange or model-token statistics. Unknown operations, reset-credit consumption and other writes receive no managed account authority. Explicit Original Destination traffic retains its original account behavior.

Subsequent owner-only banked-reset support is recorded in [ADR 0014](0014-owner-only-banked-codex-reset.md). It does not extend the captured-client operation catalog or alter the read-only behavior above.

The owner HTTP endpoint requires write/owner capability even though its verb is GET: the action uses private credentials, may refresh them and makes an outbound request. It returns only a bounded Account Observation. The native CLI receives the validated native JSON, with its real upstream account identifiers unchanged; unknown upstream fields do not enter the management projection. Observations are panel-local, keyed to the selected account/credential source and discarded on account changes, not stored in a shared current-account cache. Failed refreshes are visibly stale, never converted to zero.

Transparent routing does not rewrite `auth.json`, synthesize local account identities or assume app-server external-token support implies TUI support. Codex native identity control remains unsupported in this mode. An SSE Hold envelope can commit before provider response headers arrive, so no quota headers are appended afterward and no WebSocket-only notification is invented for HTTP SSE. Quota refresh uses the explicitly supported read operation. ACP observation mode is unchanged.

On 2026-10-18, native `GET /backend-api/codex/models` joins the captured Account Read contract at operation revision 2. It uses the current manual account overlay and the same frozen lease as other reads, accepts only a bounded `client_version` query, and returns the complete validated native catalog (at most 4 MiB). Client authorization, cookies and conditional cache headers never reach the managed account. Every read obtains a complete response; an old account's conditional request cannot produce a misleading 304. Original-account and Original Destination reads retain their existing forwarding authority. Dynamic or ambiguous account selectors remain explicitly unsupported for this bodyless operation.

Exact Route model aliases expose the advertised target's complete metadata, including access programs, service tiers and Responses Lite. Missing targets remove the alias instead of lending it unrelated capabilities. The upstream catalog ETag and inference `X-Models-Etag` share an account/credential/settings and frozen route namespace; no validator is invented when the upstream omits it. Native inference can therefore invalidate a catalog after a hidden account switch. If an earlier Hold has already committed the HTTP headers, this signal waits for a subsequent response whose headers are still available; no unsupported SSE event is added. This changes neither client Fast requests nor upstream program permissions.
