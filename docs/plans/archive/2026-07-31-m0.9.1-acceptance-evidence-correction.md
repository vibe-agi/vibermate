## Objective and outcome

This narrow correction changed acceptance evidence only. Production runtime,
Access, protocol, Exchange, Hold, proxy, provider, and Host behavior remained
frozen.

The v5 contract now:

1. requires a Codex-surfaced HTTP 426, the proxy's bounded 426-to-HTTP
   connection audit, and the exact Runtime Activity reason from the subsequent
   HTTP Exchange;
2. reports Codex Hold completion only as completion through the Responses
   streaming path, without claiming multiple client-visible deltas or TUI
   per-token rendering;
3. reports the actual approved Codex tool, `exec`, rather than Claude's
   `Write`.

Official fixed-client source inspection established an important evidence
boundary: Codex CLI 0.145.0 treats the prewarm 426 as an immediate silent
transport switch. Its retry-exhaustion fallback warning is not emitted on that
path. The selected evidence therefore triangulates the client-surfaced 426,
the two proxy connection phases, and Runtime Activity; it does not invent a
nonexistent fallback event.
