# 用量报表：刷新反馈与 API 等价费用

## 目标与页面规划

页面的任务是回答：这个 Runtime 在选定期间用了多少、哪些账号/模型贡献最多、折合 API 参考价多少钱。面向本地 App、本地 Web 和已登录运行用户；沿用同一份权限隔离后的报表，不要求开启正文录制。

```text
使用概览                         统计设置
7 天 / 30 天 / 90 天 / 365 天
当前 Runtime · 统计区间       已更新 HH:mm:ss  刷新
调用 | 成功/成功率 | 失败/取消 | 输入 | 输出 | API 等价费用
价格来源、价格更新时间、计价覆盖（紧凑说明，可查看口径）
每日趋势                      请求 / 估算费用
流量策略 / 上游账号 / 上游模型 / 流量来源
名称 | 调用 | 失败 | 未缓存输入 | 缓存读取 | 输出 | 估算费用
运行用户详情（已有功能，保持折叠）
```

- 六个概览指标使用同高、同间距的网格：宽屏一行，较窄三列，手机两列；不再叠加大段解释卡片。
- 使用既有主题：画布 `#10151A`、面板 `#182028`、分隔 `#303C47`、正文 `#F1F5F8`、数据蓝 `#75B8F0`、提示黄 `#E5B663`。亮色沿用现有配色，不硬编码新颜色。
- 标题沿用系统字体 22/13px；正文 13px、辅助信息 11–12px；金额和计数使用等宽数字。价格口径说明不是警报，不做大黄色框。
- 标志性细节是费用始终伴随“计价覆盖”：金额和可信程度在同一视觉层级，不把不完整数据伪装成准确账单。
- 图表复用现有柱图，增加费用切换；365 天费用按月汇总，避免 365 根不可读细柱。请求的年度热图保留。
- 账号/模型名称左对齐、数值右对齐，表格窄屏横向滚动；tooltip 与键盘语义保留。

设计复核：不另建一套财务仪表盘，不用装饰渐变、突出收益或夸大“省钱”；保留用户已经熟悉的深色工作台和分组结构，降低扫描成本。

## 计价边界

- 按用户确认，用量报表 schema 统一为 `vibermate-runtime-usage-report-v1`，同步消费者与测试，不保留尚未发布的 v5/v6 兼容分支。
- 名称为“API 等价费用（估算）”，美元，按当前 models.dev 参考价重算；不是包月扣费、账单或历史结算价格。
- models.dev `/api.json` 提供每百万 Token 的输入、输出、缓存读写参考价；通过现有 Runtime 辅助网络出口（Hold、审计、超时）获取，不发送账号、模型使用记录或正文。
- 首版对 OpenAI、Anthropic、Google 官方目录做精确模型 ID 匹配；允许其显式目录前缀，不截断版本号、不模糊匹配私有别名、不选择聚合商最低价。重名不猜测。其他模型标未定价。
- 每条已结束请求先分项估算，再汇总到总计、日期、账号、模型、策略和来源；失败请求有声明用量也计入。
- 推理 Token 是输出的子集；若目录单列推理费率，输出扣除推理部分后分别计价，否则只使用输出合计。避免双算。
- 缓存 Token 不再按普通输入计价；缺少 Token、价格、模型或可识别阶梯条件时保留不完整状态。已知零与未知分开。
- 采用精确十进制计算并汇总为纳美元；前端只格式化，不计算价格。不支持的模式/媒体专项收费明确不在首版范围内。
- 有上下文阶梯时使用协议声明的输入合计选择阶梯；不能判定则只显示已知下限/缺失覆盖，不宣称准确。
- 目录缓存在 Runtime 内存中 6 小时；更新失败保留旧快照并标过期，冷启动不可用不阻塞请求转发或已有用量展示；不建立第二套数据库账本。

## 刷新

- 复用已有 5 秒可见性轮询，只有用量页面可见时刷新报表；离开页面、隐藏 App/Web 后停止。
- 用量刷新独立于账号/用户管理查询，避免无关查询失败导致报表不更新。
- 并发刷新合并，手动刷新必须等待实际请求完成；切换期间防止旧范围覆盖新范围。
- 刷新保留旧内容、不闪空屏；显示加载状态、秒级更新时间和可见错误。明确仅已结束请求进入统计。
- App 管理页和 Web 成员页使用相同口径和可见性行为。
