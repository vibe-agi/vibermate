## 范围与顺序

本计划合并用户本次账号界面/代理/OAuth 要求，以及上一轮已完成 review 的启动上下文、运行概览和统计性能待办。新 goal 已建立，按以下依赖順序推进。历史已修复问题只做相关回归。

### 1. 账号通用出口与刷新策略

- [x] ProviderAccount 可选择已有“网络出口方案”，不在账号表单重复填写代理主机、端口或凭据。空选择表示继承请求所用流量策略；显式直连是一个明确选择。
- [x] 优先级：账号显式方案 > 当前请求流量策略方案 > 现有默认方案。账号设置属于共享账号，所有引用该账号的策略均生效；保存后从下一次取得账号配置的请求开始，在途请求保持原有快照。
- [x] 同一账号的模型调用、重试、额度/历史读取、重置券操作、模型发现以及 OAuth 刷新等实际支持的操作使用同一出口选择规则。没有 profile 上下文的账号管理操作使用账号方案或现有管理默认值。
- [x] 基础能力面向所有 ProviderAccount，按账号/操作能力决定 UI，避免写死 Codex 或某个 Agent。账号范围的出口不扩展其可访问上游 origin 的授权。
- [x] 方案不可用、被禁用或已删除时明确报错，不能自动改为直连。引用保护、连接复用键、故障重试、审计证据与配置修订一致。
- [x] OAuth 自动刷新为可保存的账号策略：新导入默认关闭，ViberMate OAuth 登录创建默认开启；用户可显式切换。重新导入/替换已有账号时保留用户明确设置，不凭入口重置。
- [x] 关闭自动刷新后，后台和请求前准备均不能暗中旋转 token；用户明确点击“刷新 OAuth”仍可执行一次刷新。关闭不会撤销当前有效凭据；不支持刷新能力的账号不显示可用开关。
- [x] 账号设置有明确、完整的当前结构；不根据缺失字段猜测旧刷新行为，不在运行时双读旧结构。设置变更有并发修订检查，错误时恢复显示；凭据轮换中的操作保持一致。

覆盖场景：账号 US/策略其他出口、显式直连/继承、无 profile 的额度刷新、代理不可达、账号切换、在途请求、并发自动/手动刷新、重启恢复、账号被多个策略引用、API-key/Bearer 与未来 OAuth 适配。

### 2. 账号界面与可用账号卡片

- [x] 可用账号按可比较的主要额度窗口重置时间正序排列，越快重置越靠上，优先消耗即将重置的额度（按用户最新更正）；缺失/过期时间排最后、排序稳定。多个独立额度窗口保留各自标签，不将不同额度混成一个百分比。
- [x] 以 `5d6h`、`6h20m` 等紧凑形式显示剩余时间；过期快照提示待刷新，不伪造负数或自动归零额度。倒计时本地更新，不为每张卡片反复联网。
- [x] 邮箱下面展示已用比例/进度，达到 70% 使用警示色、达到 90% 使用错误色，同时保留百分数，未知值不显示成 0%。
- [x] “启用”和“已启用”使用同尺寸、同对齐的控制；当前选中态明确，切换中禁止重复提交。当前启用账号不因排序刷新失去标识或焦点。
- [x] 账号组标题右侧增加刷新按钮，与已有链接管理入口协调；复用并发合并、缓存、限流和失败状态，一次只刷新相关账号。
- [x] Pro/Plus/Max 等套餐标签放在账号图标下方，小尺寸文本仍可辨认；缺失标签不占空位，完整含义可查看。
- [x] 上游账号展开区加入出口下拉；摘要能看清是继承还是显式方案。OAuth 状态区换成“自动刷新”开关，同时保留凭据失效/需要重连等健康信息。
- [x] 桌面表格仅在列头显示一次“自动刷新”及说明，账号行使用紧凑原生开关；凭据异常归账号身份区，不支持刷新显示 `—`。窄屏卡片保留局部标签；缩小绘制不缩小点击区，读屏独立声明账号及开关状态，混合账号列对齐。
- [x] 检查“试跑配置”的实际能力。若是纯配置诊断，移至编辑/高级入口并使用能说明用途的文案；移除普通详情页的突兀主操作，保留有用的检查能力。不得把静态试跑描述成已验证真实代理连通性。

沿用既有 Flutter 深浅主题、系统字体与 tabular figures。账号卡片结构为图标/套餐列、名称/邮箱/额度列、倒计时/启用列；不增加重复边框。保证窄屏换行、触屏点击面积、键盘焦点和读屏标签。
