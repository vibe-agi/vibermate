# 第一阶段：把现有版本打磨成正式可用版本

日期：2026-09-23。范围：性能、操作逻辑、UI、可用性，以及托管 Codex 账号的手动重置券功能。
数据引擎扩展属于第二阶段；外部系统、知识库与其他服务的对接属于第三阶段。

## 顺序与验收

1. **测量，再改慢处。** 用隔离合成记录分别计时证据提交、索引、控制接口、Flutter
   解码和可见帧，涵盖短会话、大历史、长正文、本机 App、浏览器和远程 Server。
   当前已有存储、debug Flutter 测试渲染器、Chrome 合成渲染、release App、本机及
   远程 Web 的分段基线，[测量与口径](../storage-and-read-performance.md)已列出；已修复
   经测量证实的同步索引、长 Markdown、重复刷新和远程静态资源传输成本。
2. **修好主要任务路径。** 从接入、首条记录、账号管理、策略草稿与发布、运行记录、
   到诊断错误逐一走 App 与 Web。展示实际生效的修订、账号及来源；错误说明失败位置和
   下一步。桌面、390px、键盘与中英文都要经过截图和交互验收。
3. **补 Codex 重置券。** 额度页区分充值积分与已存的限额重置券；只有受管 Codex OAuth
   账号可选择具体可用券。用户确认后才通过 Owner 管理接口消费，响应区分已重置、
   已处理、无需重置、无券和结果未确认。相同账号与券使用稳定上游操作号；重试不会
   悄悄改用另一张券。确认取消不出站，绝不购买付费即时重置。
4. **完成发布门槛。** 全量 Go/Flutter 与针对性的 race、App/Web 交互和隔离实进程测试
   通过；新旧 SQLite 数据目录升级能保留记录和审计序号；macOS 包完成签名、公证、
   Gatekeeper 和安装验证。核对 Linux 包、Release、Homebrew 与官网后发布。

不以单条 SQL 微基准或无错误截图代替真实操作验收。运行中策略和现有数据的行为不得
因为新功能变化。需要真实充值券的消费测试时，只能由持券人明确选择测试账号和具体券；
普通 CI 使用合成凭据与模拟上游，不会消耗个人账号资产。

## 本机 Web 交互检查进度

2026-09-23，以隔离临时数据目录启动原生 Web Runtime，使用 Playwright Chromium 在
1440px 与 390px 实际完成所有者初始化、恢复密码、登录、查看接入命令、添加合成上游
账号、关联服务、添加备注并搜索、创建并发布一条含固定账号的流量策略。发布前检查原先
只显示旧运行记录影响，现已从服务端审核后的草稿展示即将发布的路由、账号及记录设置；
桌面和窄屏截图均复查。Codex OAuth 点击“开始登录”只展示授权链接，没有自动打开新页。
未使用真实访问令牌或向服务商发送请求。

随后补齐了 Web 的手动代理登录接口与远程 CA 下载：本机 HTTP、容器 HTTP、远程
HTTPS 分别用隔离浏览器和合成凭据完成所有者登录、手动代理创建与证书交付；服务端
集成测试覆盖成员拒绝、凭据轮换/撤销、DNS/IP 严格 TLS 和本地假上游的代理流量。
浏览器下载的 Proxy CA DER 指纹与交付页一致。390px 设置导航改为显示完整名称的
选择器，并用 Playwright 实际键盘切换页面。

随后发现直接从 macOS App 包内运行 `vibermated server` 时未定位同包 Web 资源，
进程虽启动却报告 `managementUi:false`。服务器模式现复用已有的包内资源定位，并保留
独立可执行文件旁的 Web 目录规则；打包后实进程报告 `managementUi:true`。重新用
390px Playwright 完成首次建 Owner、登录、创建专用代理登录、撤销，以及空记录页的
“创建代理登录”主按钮和键盘 Enter 打开创建弹窗。Web Owner 的首次入口不再只提示
终端，窄屏账号菜单也无横向溢出。隔离测试目录已移入废纸篓。

容器本机模板的测试暴露出旧的版本化本地镜像名与端口 `0` 交付地址问题：现统一用
`vibermate-runtime:local` 表示当前源码构建，冒烟脚本先选定一个空闲回环端口，避免
把 `127.0.0.1:0` 作为代理地址。默认构建及 Compose 冒烟已通过初始化、登录、CA
交付和重启恢复；一次性诊断数据卷与测试镜像已删除。

发布版 v0.1.13 的精确 schema 摘要回归同时放入一条 Conversation/Exchange 和一条
EgressAttempt：升级后记录、投影 ID 及两条审计序号均保留，新写入继续递增。公开
v0.1.13 Linux 实进程另行创建 Owner、Endpoint、Account 和已发布 Environment，随后
v0.1.14 从同一数据目录启动，全部读回且新写入成功。

本机打包 App 独占 GUI 验收没有作为成功计入：安装版退出后，测试用空的
`CFFIXED_USER_HOME` 隔离 HOME，会触发 `secret_store_unavailable`。同一包的 sidecar
在正常环境通过 Flutter live Runtime 测试，添加该变量后稳定复现钥匙串失败；这是
测试隔离方式与本机 Keychain 的兼容问题，尚不能推断正式签名包失效。没有删除或
更改用户钥匙串条目。最终精确发布包已在干净 runner 的正常 HOME 中完成 Developer ID
签名、Apple 公证/stapling、Gatekeeper、只读 DMG 安装和两次 App 启动。

原始 HTTP 页的脱敏诊断现在先显示可检查的 JSON，再由用户明确复制；取消不会写入
剪贴板。诊断包移除了客户端路径及 Content-Type/Encoding 等可由请求控制的字段，
保留阶段、修订、时间、状态和证据边界；390px 的原始 HTTP 与 Thinking 标题栏也不再
横向溢出。版本、连接/DNS/TLS/OAuth 等故障的可行动提示、技术详情和脱敏预览已通过
结构测试与浏览器典型路径验收。

2026-09-26，v0.1.14 候选又完成本机与远端 Web 的 Owner API + Playwright 合成试跑、
长正文和延迟链路测量，以及公开 v0.1.13 Linux 实进程到当前二进制的同目录升级。
账号、Environment 和后续写入均保留；测试主机上的临时进程、凭据和数据已清理。
完整口径与数值见[发布验收记录](../evidence/2026-09-26-phase-one-release-acceptance.md)。

第一阶段发布门槛已完成：`main` 合并提交 `b0525c4` 通过受保护签名、公证与安装流程，
GitHub v0.1.14 Release、Linux 双架构资产与校验和、Homebrew cask 和官网均指向同一
标签。本机另一套 ViberMate Desktop 未被关闭或修改；最终安装版启动由干净 runner
完成。精确流程与外部交付链接见[发布验收记录](../evidence/2026-09-26-phase-one-release-acceptance.md)。
